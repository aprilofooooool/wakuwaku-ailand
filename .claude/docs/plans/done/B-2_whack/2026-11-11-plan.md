# キャラたたき（whack）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 3本目のゲーム「キャラたたき」（1回50秒、3×3の穴から自分のキャラをタッチ。1人／2人同時（iPad 横）／2人交代）を作り、入口から遊べるようにする。

**Architecture:** 素の HTML/CSS/JS（IIFE、`window.Ailand`、file:// で動く）。core を3点だけ拡張する（`Pointer` の `onPress`、新規 `core/loop.js`、`smug` 表情）。ゲームは `games/whack/` に drop4 と同じ分け方で置き、ルール（engine）と進行（controller）は DOM なしの純粋なコードにして Node でテストする。出方は開始前に乱数の種から全部決める（設計 §2.2）。

**Tech Stack:** Vanilla JS（ES5 スタイル、`var`・IIFE）、Node の vm で動くテスト（`tests/run-node.js`）、ブラウザ用テスト `tests/test.html`。

**Spec:** `.claude/docs/specs/2026-11-11-whack-design.md`（以下「設計」）。backlog: B-2（`.claude/docs/plans/backlog.md` が正）。

## Global Constraints

- ES Modules・fetch・Worker・外部 CDN・外部フォント禁止。file:// で動くこと（`tests/static-check.js` が検査）。localStorage は `core/storage.js` 経由だけ。
- ファイル名・フォルダ名は `^[a-z0-9.-]+$`。新しいテストファイルはすべて `tests/test.html` に載せる（static-check が検査）。
- 画面の文言はひらがな中心。コード・識別子・コメントは英語。セリフは1つ20文字以内、公式セリフは使わない。
- 操作規約：プレイ領域とボタンに `touch-action: none`。穴以外のタップ領域は 64×64px 以上、穴も 64px 以上。本文 18px 以上。基準幅 iPhone 縦 390〜430px。
- 保存キーは `ailand:whack:settings.v1` と `ailand:whack:best.v1` だけ（`Storage.create('whack')` の `settings.v1` / `best.v1`）。途中の状態は保存しない。
- 既存ゲームの挙動を変えない：`Pointer.attach` の既存ハンドラ（onHover/onTap/onLeave）の動き、drop4・オセロっちのテスト、`scripts\run.bat replay-othello` が golden と一致すること（golden `tests/golden/othello-replay.json` は再生成しない）。
- `prefers-reduced-motion` のとき：出入りはフェード、跳ねる・揺れる・点滅なし（設計 §5.3）。
- コマンドは `scripts\run.bat test` / `scripts\run.bat check` / `scripts\run.bat replay-othello`（約3.5分、background で実行）。
- コミットは `<type>: <日本語要約>`、末尾に `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`。ブランチはこのワークツリーのブランチ。push しない。
- プロセスを止めるときは自分が起動した PID だけ（プロセス名指定の停止は禁止）。

## Review Focus

1. 2人が同じフレームで左右の穴を同時に押すと、両方の点が入る。→ Task 1 のテスト `two pointers pressing at once both report`、Task 9 の browser-only テスト `simultaneous presses on both sides both score`。
2. 一時停止（タブ非表示・回転・「もどる」の確認・せってい）から戻ったとき、止まっていた時間ぶん時間が飛ばない。→ Task 2 のテスト `start after stop does not catch up`、Task 7 のテスト `paused advance does not move time`。
3. 引っこむ瞬間・引っこんだ後・当てた後の押下は点にならない（同じキャラで二度点が入らない）。→ Task 5 のテスト `press at the hide boundary and after a hit does nothing`。
4. 0点のときにダメのキャラを押しても点は0のまま、表示用の差分は −3。→ Task 5 のテスト `score never goes below zero`。
5. 保存された設定が壊れている（知らないキャラ、2人が同じキャラ、players が 3、difficulty が不明）とき、既定値で開く。→ Task 7 のテスト `broken settings fall back to defaults`。

### Task 4: whack の定数と出方の表（buildSchedule）

**Files:**
- Create: `games/whack/js/namespace.js`、`games/whack/js/constants.js`、`games/whack/js/engine.js`（この Task では `buildSchedule` と `ngIdsFor` だけ）
- Test: `tests/whack/schedule.test.js`
- Modify: `tests/test.html`（whack の js を drop4 の js の後に、テストを drop4 のテストの後に足す。以降の Task も同様に追記）

**Interfaces:**
- Produces（`Ailand.games.whack.Constants`）：
  - `DURATION_MS = 50000`、`FINAL_MS = 10000`（最後の10秒の始まりは `DURATION_MS - FINAL_MS`）、`COUNTDOWN_MS = 3000`、`HOLES = 9`、`REACT_MS = 600`、`COOLDOWN_MS = 300`、`FIRST_SPAWN_MS = 600`、`RARE_GAP_MS = 6000`、`POINTS = { self: 1, rare: 5, ng: -3 }`。
  - `DIFFICULTY = { easy: {...}, normal: {...}, hard: {...} }`、各 `{ intervalStart, intervalEnd, upStart, upEnd, finalFactor, maxStart, maxFinal, ngRate, rareRate }`。値は設計 §2.2 の表そのまま（easy: 1100, 700, 1600, 1100, 0.8, 2, 3, 0.15, 0.05 ／ normal: 900, 500, 1300, 850, 0.8, 2, 4, 0.20, 0.05 ／ hard: 700, 380, 1050, 650, 0.8, 3, 4, 0.25, 0.05）。
- Produces（`Ailand.games.whack.Engine`）：
  - `buildSchedule(difficulty: string, seed: number) → Spawn[]`。`Spawn = { at, hole, kind: 'self'|'ng'|'rare', ngPick, upMs, busyUntil }`（`busyUntil = at + upMs + REACT_MS`）。`at` の昇順、すべて `at < DURATION_MS`。
  - `ngIdsFor(selfId: string) → string[]`：`Characters.list()` の順で selfId 以外の id。
- 生成のしかた（決まっていないと実装がぶれるので固定する）：`rng = Ailand.core.Rng.mulberry32(seed)`。`t = FIRST_SPAWN_MS` から始め、`t < DURATION_MS` の間くり返す。`p = t / DURATION_MS`、`final = t >= DURATION_MS - FINAL_MS`。`interval = lerp(intervalStart, intervalEnd, p) * (final ? finalFactor : 1)`、`upMs = round(lerp(upStart, upEnd, p))`、`max = final ? maxFinal : maxStart`。使用中（`busyUntil > t`）の数が `max` 未満で、空いている穴（`busyUntil + COOLDOWN_MS <= t`、一度も使っていない穴を含む）があれば1つ出す：穴は `floor(rng() * 空き数)` 番目、種類は `r = rng()` で `r < rareRate` かつキラカードの制約（使用中のキラカードなし・前のキラカードの `at` から `RARE_GAP_MS` 以上）を満たせば rare、`r < rareRate + ngRate` なら ng、それ以外は self（rare の制約で外れたら self）。`ngPick = rng()`。出しても出さなくても `t += round(interval)`。rng を呼ぶ順番は「穴→種類→ngPick」で固定し、出さないときは呼ばない。

- [ ] **Step 1: 失敗するテストを書く**
  - `same seed gives the same schedule`：`buildSchedule('normal', 42)` を2回 → `toEqual`。別の種（43）では違う。
  - `schedule stays inside 50s and is sorted`：3つの難しさで全部 `at < 50000`、`at` は昇順、`hole` は 0〜8、`busyUntil === at + upMs + 600`。
  - `gaps shrink over time and in the final 10s`：normal・種 1 で、0〜10秒の平均間隔 > 30〜40秒の平均間隔 > 40〜50秒の平均間隔。
  - `visible count never exceeds the cap`：各 `at` で使用中の数（自分を含む）が、40秒前は `maxStart`、以降は `maxFinal` 以下。
  - `a hole rests 300ms before it is used again`：同じ穴の連続する2つで、後の `at >= 前の busyUntil + 300`。
  - `rare is single and spaced`：rare どうしの `at` の差 ≥ 6000、rare の使用中に別の rare が始まらない。種 1〜20 のどれかで rare が1つ以上ある。
  - `ng share is near the rate`：hard・種 1〜20 を合わせて、ng の割合が 0.18〜0.32。
  - `ngIdsFor excludes self`：`ngIdsFor('mimitchi')` → `['mametchi', 'kuchipatchi', 'flowertchi']`。
- [ ] **Step 2:** `scripts\run.bat test` → FAIL。
- [ ] **Step 3:** namespace・constants・engine（buildSchedule・ngIdsFor）を書く。
- [ ] **Step 4:** `scripts\run.bat test` と `check` → PASS。

### Task 7: 進行（controller）

**Files:**
- Create: `games/whack/js/controller.js`
- Test: `tests/whack/controller.test.js`

**Interfaces:**
- Consumes: `Engine`（Task 4・5）、`Ailand.core.Storage`（テストでは `_backend` を差し替えた Storage か、`get/set` を持つ偽物）、`Ailand.core.EventBus`。
- Produces（`Ailand.games.whack.Controller.create({ bus, storage, seed })`。`seed()` は新しい種の整数を返す関数）：
  - `loadSettings() → { players: 1|2, chars: [id, id], difficulty }`。既定 `{ players: 1, chars: ['mametchi', 'kuchipatchi'], difficulty: 'easy' }`。players が 1/2 以外、知らないキャラ、2体が同じ、difficulty が `DIFFICULTY` にない → 既定値。
  - `bestOf(difficulty) → number`（記録なしは 0）。
  - `start(settings, mode: 'solo'|'together'|'turns')`：設定を `settings.v1` に保存。種を1つ取り `buildSchedule` を1回だけ作る。Side は solo:1つ、together:2つ（同時に進む）、turns:2つ（1人ずつ）。phase を `'countdown'` にする。
  - `advance(ms)`：一時停止中・`phase` が `'countdown'`/`'playing'` 以外なら何もしない。countdown：残り 3000→0 の間に `bus.emit('count', { n })`（n = 3, 2, 1 を各1秒の頭で1回ずつ）、0 になったら `emit('go', { player })` して `'playing'`。playing：`elapsed += ms`、動いている Side ごとに `Engine.step` し、各 Event を `emit(e.type, { side, ...e })`（turns のとき side は 0 固定にせず、プレイヤー番号を入れる）。`elapsed` が 40000 をまたいだ最初の1回だけ `emit('final10', {})`。全 Side が end したら、turns の1人目なら phase `'handoff'` と `emit('turnEnd', { player: 0, score })`、それ以外は phase `'result'` と `emit('result', getResult())`。
