# ピタうめっち（fill）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 7本目のゲーム「ピタうめっち」（1人用。絵の形の枠をポリオミノのピースで埋めると枠がドット絵に変わり、ずかんに貼られる）を作り、入口から遊べるようにする。

**Architecture:** 素の HTML/CSS/JS（IIFE、`window.Ailand`、file:// で動く）。`games/fill/` にぷにっち（`games/chain/`）と同じ分け方で置く。ピースの計算（piece）・問題作り（puzzle）・遊びの決まり（engine）・反応（reactions）・進行と保存（controller）は DOM なしの純粋なコードにして Node でテストする。盤は Canvas、ずかん・置き場・ボタン・キャラは HTML。`piece.js` はほかのファイルに頼らない形にし、ピースじんとりで `core/` へ移せるようにする（設計 §12 の案1）。

**Tech Stack:** Vanilla JS（ES5 スタイル、`var`・IIFE）、Node の vm で動くテスト（`tests/run-node.js`、`describe`/`it`/`expect`）、ブラウザ用テスト `tests/test.html`。絵を作る道具は Node（`tools/fill-pictures/`）。

**Spec:** `.claude/docs/specs/2026-11-17-pita-design.md`（以下「設計」）。見本：`games/chain/` と `.claude/docs/plans/done/B-7_puni/2026-11-15-plan.md`。backlog: B-8（`.claude/docs/plans/backlog.md` が正）。

## Global Constraints

- ES Modules・fetch・Worker・外部 CDN・外部フォント・`getImageData` 禁止。file:// で動くこと（`tests/static-check.js` が検査）。localStorage は `core/storage.js` 経由だけ。
- ファイル名・フォルダ名は `^[a-z0-9.-]+$`。新しいテストファイルはすべて `tests/test.html` に載せる（static-check が検査）。
- ゲーム id は `fill`、表示名は「ピタうめっち」。名前空間 `Ailand.games.fill`。効果音名は `fill-` で始める。
- 画面の文言はひらがな中心。コード・識別子・コメントは英語。セリフは1つ20文字以内、公式セリフは使わない。既存の作品・キャラの名前・見た目に似せない（設計 §1.3・§3.2）。
- 操作規約：盤・置き場・ボタンに `touch-action: none; user-select: none; -webkit-user-select: none; -webkit-touch-callout: none`。ボタンは 64×64px 以上、本文 18px 以上。iPhone 縦 390×844px でスクロールなしに全部収まる（設計 §4.4）。
- 保存キーは `ailand:fill:settings.v1` と `ailand:fill:zukan.v1` だけ（`Storage.create('fill')`）。途中の状態は保存しない。BGM の ON/OFF は `core` の `Sound` 側（設計 §8）。
- 選んだキャラに `worried`・`sadness`・`anger`・`panic` を出さない（設計 §5.1）。画面全体の演出は完成のときの1つだけ（設計 §5.3）。
- `prefers-reduced-motion` のとき：弾む・光る・紙吹雪・キラキラを止め、ピースが消えて絵が出るだけ（設計 §5.2）。
- ピース4〜5マス。むずかしさの表（枠のマス数）：easy 20〜30・normal 30〜40・hard 40〜50。絵の上限 easy 24×24・normal 28×28・hard 32×32 ドット。1マス＝4×4ドット。ヒントの影 2000ms（設計 §2.2・§2.5・§2.6）。
- 既存ゲームのファイルと既存のテストを変えない（`tests/core/games.test.js` の ready 数・fill 行と `tests/core/bgm-scores.test.js` の比較対象を増やす以外）。
- コマンドは `scripts\run.bat test` / `scripts\run.bat check` / `scripts\run.bat serve`（ブラウザ確認、`http://127.0.0.1:8080/`）/ `scripts\run.bat fill-pictures`（Task 2 で足す）。
- コミットは `<type>: <日本語要約>`、末尾に `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`。ブランチは `feat/fill`。push しない。main へのマージはユーザーの了承を得てから。
- プロセスを止めるときは自分が起動した PID だけ（プロセス名指定の停止は禁止）。

## Review Focus

1. ドラッグしたピースを、半分だけ枠からはみ出した所・ほかのピースに重なる所・置き場の上・画面の外で離した → どれも置き場に戻り、盤にピースの一部だけが残ることはない。→ Task 4 `out of frame or overlap returns to the tray`、Task 8 `dropping outside the board returns the piece`。
2. 同じ形のピースを入れ替えて置いた・答えの一例と違う並べ方で全部埋めた → クリアになる。→ Task 4 `clear with a different arrangement`。
3. 盤のふちや別のピースのすぐ横に置いたピースをまわす・うらがえす → 入るならその場で向きが変わり、入らなければ新しい向きで置き場に戻る。重なったまま残らない。→ Task 4 `turning a placed piece stays or returns`。
4. ずかんの保存値が壊れている・知らない絵の id がある・キラキラ済みの絵をヒントありでもう一度クリアした → 開ける。知らない id は無視し、キラキラは消えない。→ Task 6 `broken zukan falls back`・`sparkle never goes away`。
5. ドラッグ中に2本目の指がふれた・ドラッグ中に pointercancel が来た（着信・ジェスチャー）→ 2本目は無視。cancel ではピースが置き場に戻り、ドラッグの影が残らない。→ Task 8 `a second finger is ignored`・`pointercancel returns the piece`。

**Interfaces:**
- Produces（`Ailand.games.fill.Constants`）：`DOTS_PER_CELL: 4`、`PIECE_MIN: 4`、`PIECE_MAX: 5`、`MAX_TRIES: 1000`、`HINT_MS: 2000`、`PLACE_REACT_RATE: 1 / 3`、`CHARS: ['mametchi', 'kuchipatchi', 'mimitchi', 'flowertchi']`、`LEVELS: ['easy', 'normal', 'hard']`、`LEVEL: { easy: { minCells: 20, maxCells: 30, maxDots: 24 }, normal: { minCells: 30, maxCells: 40, maxDots: 28 }, hard: { minCells: 40, maxCells: 50, maxDots: 32 } }`、`MAX_COLORS: 8`、`PER_LEVEL: 8`。
- Produces（`Ailand.games.fill.Piece`。`Ailand.games.fill` 以外の名前を参照しない）：
  - `normalize(cells) → cells`、`rotate(cells) → cells`（右回り1回）、`flip(cells) → cells`（左右）、`orient(cells, rot, flip) → cells`、`orientations(cells) → [{ rot, flip, cells }]`（形が同じものを除いた一覧）、`same(a, b) → boolean`（normalize 後に同じ並び）。
  - `place(cells, x, y) → [[x, y], …]`（盤の上の絶対位置）。
  - `fits(frame, occupied, cells, x, y) → boolean`：`frame` は `{ w, h, on: boolean[y][x] }`、`occupied` は `{ 'x,y': pieceId }`。全マスが枠の中で、`occupied` にないとき true。
  - `partition(frameCells, rand, min, max) → [[cells(絶対位置)], …] | null`：`rand` は `() → [0, 1)`。全マスがちょうど1回入る・各ピースが上下左右でつながる・大きさ min〜max。作れなければ null（やり直しは puzzle が行う）。
  - partition のやり方（決めにくいので指定）：まだ入っていないマスのうち「空いたとなりが最も少ないマス」から始め、`min〜max` から乱数で決めた大きさまで、となりの空きマスを乱数で（空いたとなりが少ないものを優先して）足していく。足せずに min に届かない、または残りの空きマスの島のどれかが min マス未満になったら null。

  - `rotate four times returns the same`・`flip twice returns the same`：L字5マスで確かめる。`rotate` の1回目は `[[0,0],[0,1],[0,2],[1,2]]`（縦棒＋右下）→ `[[0,0],[1,0],[2,0],[0,1]]`。

  - `partition is deterministic for the same rand`：同じ種の `Ailand.core.Rng.mulberry32` で2回 → 同じ結果。

  - `hintUsed() → boolean`。
