# BGM の曲調の作り分け（B-4）実装計画

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** トップと3ゲームの BGM を、調・リズム・音色・テンポで聞いてすぐ分かるように作り分ける。

**Architecture:** `core/bgm.js` の楽譜に「省略できる項目」（音色・音量・スイング・打楽器・すくい上げ・きらっと音・和音の複数音）を足す。省略時は今と同じ鳴り方。4曲の楽譜は、承認済みの試作 `.claude/docs/specs/bgm-drafts/bgm-trial.html` の `SONGS` をそのまま各ゲームのファイルへ移す。

**Tech Stack:** Vanilla JS（IIFE、`Ailand` 名前空間）、Web Audio。テストは自前ランナー（`tests/test.html` に並べたファイルを `scripts\run.bat test` が node で実行）。

**Spec:** `.claude/docs/specs/2026-11-12-bgm-variety-design.md`

## Global Constraints

- 音声ファイル・外部ライブラリを足さない。file:// でも動く。
- 楽譜の音は 100〜1600 Hz、メロディの9割以上は 400〜1200 Hz。打楽器と `sparkle` の重ね音（楽譜の音から作る1オクターブ上）は対象外（判断：spec §4 が sparkle を「1オクターブ上」と定めているため）。
- 足す項目はすべて省略できて、省略時は今と同じ鳴り方（spec §4）。
- 音量：メロディ既定 0.32、低音 0.38→0.34、和音 0.12→1音あたり 0.08、キック 0.55、スネア 0.32、ハイハット 0.18。
- オセロっちの `games/othello/js/game/`・`engine/` と `tests/golden/othello-replay.json` は変えない。
- コミットは `<type>: <日本語要約>`。テストは `scripts\run.bat test`、静的チェックは `scripts\run.bat check`。
- プロセスは名前で止めない。自分が起動した PID だけ止める。

## Review Focus

1. 打楽器が鳴っている途中で BGM を止める（おと OFF・画面を戻る）→ 雑音の音源も止まる。Task 2 のテスト `stop() also stops drum noise sources`。
2. スイングの曲の途中でテンポを変える（ぽとん4の終盤）→ 音の開始時刻が逆戻りしない。Task 2 のテスト `swing stays in order across a tempo change`。
3. AudioBuffer や BiquadFilter を作れない環境（古いブラウザ・テストの偽物）→ 雑音の打楽器だけ鳴らさず、例外を出さない。Task 2 のテスト `no noise support: snare and hat are skipped without throwing`。
4. 打楽器の楽譜が、メロディと長さのちがう列でも、それぞれの長さでくり返す。Task 1 のテスト `drums loop on their own length`。
5. 矩形波・のこぎり波のメロディや打楽器が効果音・セリフをかき消す → 自動では測れないので Task 4 の手動テスト項目に入れる。

### Task 1: `notesBetween` が和音の複数音・打楽器・スイング位置を返す

**Files:**

**Interfaces:**
- Produces：`Bgm.notesBetween(sc, bpm, fromBeat, toBeat)` の各要素は `{ beat, at, freq, len, bass }` に、和音なら `chord: true`、打楽器なら `drum: 'k'|'s'|'h'|'ks'`（`freq` は 0）。
  - `beat`：拍の数え方は今と同じ（スイングで変えない）。範囲 [from, to) の判定は `beat` で行う。
  - `at`：実際に鳴らす拍。`sc.swing > 0` で `beat` の小数部が 0.5（誤差 1e-9 以内）のとき `beat + sc.swing`、それ以外は `beat`。
  - 和音の高さが配列のときは、配列の音ごとに1つずつ要素を返す（同じ `beat`）。
  - `sc.drums` の列は、メロディ・低音・和音と同じく自分の長さでくり返す。

### Task 2: 新しい項目で鳴らす（音色・音量・すくい上げ・きらっと音・打楽器・スイング）

**Files:**
- Modify: `core/bgm.js`（定数 `BASS_PEAK`・`CHORD_PEAK`、`tick()`、`stop()`、新しい内部関数）
- Test: `tests/core/sound.test.js`（`FakeCtx` を広げ、`describe('core/Bgm voices (fake clock)', ...)` を足す）

**Interfaces:**
- Consumes：Task 1 の `notesBetween`（`at`・`drum`・和音の複数音）。
- Produces：楽譜の項目 `gate`（既定 0.92）、`melodyPeak`（既定 0.32）、`bassWave`（既定 'sine'）、`chordWave`（既定 'sine'）、`chordLen`（既定 0.12）、`bend`、`sparkle`、`swing`、`drums`。Task 3 の楽譜はこの名前を使う。

鳴らし方（試作 `bgm-trial.html` の `tone` / `drum` と同じ値）：
- 開始時刻は `nextTime + (n.at - nextBeat) * 60 / bpm`。
- メロディ：長さ `n.len * gate`、波形 `score.wave || 'triangle'`、音量 `melodyPeak`、立ち上がり 0.02。`bend` があるときは、周波数を `freq * bend` から始めて `min(0.06, 長さ / 2)` 秒で `freq` へ指数で上げる（bgm.js 内に、Sound.note と同じ形の音を作る内部関数を置く）。`sparkle` のときは `Sound.note(ctx, dest, at, freq * 2, 0, Math.min(n.len, 0.5), 'sine', 0.06, 0, 0.004)` を重ねる。
- 低音：長さ `n.len * 0.92`、波形 `bassWave`、音量 0.34、立ち上がり 0.02。
- 和音：長さ `Math.min(n.len * 0.6, chordLen)`、波形 `chordWave`、音量 0.08、立ち上がり 0.01。
- キック（'k'・'ks'）：`Sound.note(ctx, dest, at, 150, 0, 0.14, 'sine', 0.55, 50, 0.003)`。
- スネア（'s'・'ks'）：雑音 → BiquadFilter `bandpass` 1800 Hz → 音量 0.32・長さ 0.12 秒・立ち上がり 0.002。
- ハイハット（'h'）：雑音 → BiquadFilter `highpass` 7000 Hz → 音量 0.18・長さ 0.04 秒・立ち上がり 0.002。
- 雑音のバッファ：`ctx.sampleRate * 0.5` 長の1チャンネル、-1〜1 の乱数。AudioContext ごとに1回だけ作り、ctx が変わったら作り直す。`ctx.createBuffer`・`createBufferSource`・`createBiquadFilter` のどれかが無いときは、スネアとハイハットを鳴らさない（キックは鳴らす）。
- 雑音の音源も `live` に入れ、`stop()` で止める。
