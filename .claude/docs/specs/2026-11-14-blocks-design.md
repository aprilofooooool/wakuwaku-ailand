- 作成日：2026-11-14
- 状態：ユーザー承認済み（2026-11-14）

## 1. 目的

- 娘（小学校中高学年。この種の落ちものブロックゲームには慣れている）が、**ひとりでスキマ時間に数分で1回遊ぶ**ためのゲーム。
- 守る体験：ブロックにキャラの顔が付いていて、列をそろえると顔がうれしそうに飛んでいく。選んだキャラの顔を集めきったらクリア。
- 遊びの芯：**落ちてくるブロックを回して並べ、横1列をそろえて消す。消した列に入っていた「自分のキャラの顔」を目標の数だけ集める。**

### 1.1 ゴール
- 1回が数分で終わる（目標の数を集めればクリア）。
- 自分のキャラのブロックが一目で見分けられ、「自分のキャラの入った列を消そう」と狙う楽しさがある。
- 顔が消える瞬間がかわいい（うれしそうに飛んでいく）。

### 1.2 やらないこと（非ゴール）
- 2人以上・CPU の相手。
- 集めた顔の保存・図かん。最高記録（1回ごとに終わる。ユーザー指定）。
- 途中からの再開（つづきから）。§12 参照。
- ブロックの「とっておき（ホールド）」、点数、レベル表示、ランキング。
- スワイプ操作。

### 1.3 アンチゴール（動いても失敗とみなすもの）
- 消える顔がいやな顔・痛そうな見せ方をする（壊れる・爆発する・つぶれる）。
- 自分のキャラのブロックと、ほかのキャラのブロックが一目で見分けられない。
- 上手になるほど1回が長くなり、スキマ時間に終わらない。
- 自分の操作の直後に、選んだキャラがいやな顔をする（要件 1.6）。
- 1回の操作で画面全体の演出が何重にも重なる（要件 1.6）。
- プレイ中に画面がスクロール・拡大・長押しメニューを出す。ボタンを押したつもりが反応しない。
- 特定の既存ゲームの名前・見た目・音楽に似せる（要件 §5。遊びの仕組みだけを使う）。

## 2. 遊び方とルール

### 2.1 盤とブロック
- 盤は **横10×縦20マス**（判断。この種の遊びで慣れた大きさ）。盤の上に見えない2行の出現枠を持つ（判断）。
- 出したブロックは、入るかぎり見えない2行の下まですぐ下ろす（2026-11-14 実装時の判断。見えない時間をなくすため）。
- ブロックは4マスでできる **7種類の形**（I・O・T・S・Z・J・L に当たる形。名前は画面に出さない）。
- **1つのブロックの4マスには、同じキャラの顔が付く。** ブロックの色はそのキャラの色（`Ailand.core.Characters` の `colors.main` / `colors.sub`）。
- 置いたあとのマスも、顔とキャラは保ったまま残る。列が消えて上のマスが下がるときも、顔はそのマスについていく。

### 2.2 出る順
- 形：7種類を1組として混ぜ、1組を使い切ったら次の組を混ぜる（判断。同じ形ばかり・長く来ないを防ぐ）。
- キャラ：4体を1組として混ぜ、1組を使い切ったら次の組を混ぜる（判断。**選んだキャラは4つに1つ必ず来る**。「長く出ない」を防ぐ。ユーザー合意の「長いあいだ出ないことがないように」の具体化）。
- 形とキャラの組は独立に決める。乱数は `core/rng.js` の種つき乱数を使い、1回ごとに種を変える。

### 2.3 操作
- 左右に1マス動く、右回り（時計回り）に回す、1マス下げる（ゆっくり落とす）、一気に落とす。
- 回したとき壁・ほかのマスに当たる場合は、左1・右1・上1マスの順にずらして入るか試し、どれも入らなければ回さない（判断。慣れた人が「回らない」と感じにくい最小のしくみ）。
- ブロックは時間で1マスずつ落ちる。下に着いてから **0.5秒** 動かさなければ固定（判断）。着いたあとに動かす・回すと待ち時間を最初から数え直すが、数え直しは1つのブロックで15回まで（判断。いつまでも固定しないのを防ぐ）。「一気に落とす」はすぐ固定する。
- 落ちる位置の影（どこに落ちるかの薄い表示）を出す（判断。慣れた人には当たり前の手助けで、誤配置を減らす）。
- 「つぎ」に来るブロックを1つ、顔つきで盤の横に出す（ユーザー合意）。

### 2.4 消える・集める
- 横1列がすべてうまったら、その列を消し、上のマスを下げる（複数列は同時に消す）。
- 消えた列のマスの顔は、**うれしそうに飛んでいく**（§5.2）。
  - 選んだキャラの顔 → 「とくべつ枠」へ入り、集めた数が増える。
  - ほかのキャラの顔 → 「びん」へ入る（数は数えて結果に出すが、勝ち負けには関係しない）。
- **とくべつ枠の数が目標に届いたらクリア**。届いた列消しの演出が終わったところで終わる（判断）。

### 2.5 おしまい（負け）
- 新しいブロックが出る場所がふさがっていて出せないとき、「おしまい」。
- 固定したブロックの4マスがすべて見えない出現枠（盤の上の2行）の中にあるときも「おしまい」（判断）。
- 結果に「○こ あつめたよ」を出す。キャラは困った顔（`worried`）まで。`sadness`・`anger`・`panic` は使わない。

### 2.6 難しさ
- 対局前に「かんたん・ふつう・むずかしい」から選ぶ。違うのは**落ちる速さ**と**目標の数**だけ。
- 消した列の数に応じて少しずつ速くなる（判断）。数値の初期値（判断。手動テストで調整する前提。`constants.js` にまとめる）：

| 項目 | かんたん | ふつう | むずかしい |
|---|---|---|---|
| 1マス落ちる間隔（はじめ） | 900ms | 650ms | 450ms |
| 4列消すごとに掛ける倍率 | ×0.92 | ×0.92 | ×0.92 |
| 間隔の下限 | 350ms | 200ms | 120ms |
| 目標の数（自分のキャラの顔） | 12こ | 20こ | 28こ |

- 目安：1列に自分の顔はおよそ2〜3こ入るので、「ふつう」は8列前後でクリア、2〜3分で終わる見込み。これを超えて長くなるなら目標の数を下げる（アンチゴール「1回が長くなる」）。
- 「ゆっくり落とす」は、押している間 1マス／50ms で下げる（判断）。

## 3. 画面と流れ

### 3.1 共通
- 共通ヘッダー（`Ailand.core.UI.header`）：「もどる」「おと」「せってい」。
- 背景の色とトーンは、ほかの3本と見分けがつく色にする（色は実装者が決める）。見た目の土台は白いパネル・紺のふち（要件 1.9）。

### 3.2 設定画面
1. キャラ：1体を選ぶ（4体の顔を並べる）。
2. むずかしさ：かんたん／ふつう／むずかしい（目標の数を添える。例「20こ あつめよう」）。
3. はじめる
- 初めて開いたときだけ、遊び方を1画面で見せる（「そろえて けすと かおが とんでいくよ」「○○の かおを ○こ あつめたら クリア」）（判断。慣れているので短く。2回目からは設定画面の「あそびかた」ボタンで見られる）。
- 前回のキャラ・難しさを覚えておき、開いたときに選ばれた状態にする（要件 1.8）。

### 3.3 プレイ画面
- 盤（Canvas）、「つぎ」、とくべつ枠（「★ 3／20」と、選んだキャラの顔）、びん（たまった顔が見える入れもの）、選んだキャラ（反応する顔。§5.1）、操作ボタン。
- 開始前に「3・2・1・スタート！」（キャラたたきと同じ）。
- 盤の上から4行目より上にマスがあるとき、盤のふちをうっすら赤くする（判断。危ないことを、キャラの顔ではなく盤で知らせる。§1.3 のため）。
- 目標まで残り3こ以下になったら、とくべつ枠を光らせ、BGM のテンポを上げる（判断）。

画面の配置（判断。細部は実装者が決める）：

┌──────────────┐              ┌──────────────────────────────┐

│ │  盤    │ ├──┤│              │ │    │  │  盤    │  ├──┤   │

│ │        │ │キャラ││              │ └──┘  │        │  └──┘   │

- 盤の1マスの大きさは、使える枠に盤全体が収まる最大から決める。ボタンは要件 1.2 の最小 64×64px を守る。iPhone 縦 390×844px で盤・横の表示・ボタンがすべて収まり、スクロールしないこと。
- iPhone 横（高さが足りない）は、盤を小さくしても遊べる配置にする（実装者が決める）。

### 3.4 一時停止（キャラたたきと同じ考え方）
- アプリの切り替え・タブの非表示（`visibilitychange`）で止め、「つづける」ボタンを出す。
- プレイ中に「もどる」を押したら止めて「やめる？」の確認を出す。「やめる」でその回を捨てて入口へ。
- 「せってい」の中身：「さいしょから」（設定画面へ）、BGM の ON/OFF。開いている間は止める。
- 止めている間は盤を隠す（判断。止めて考える使い方を防ぐ。ただし子ども向けなので厳しくはしない：隠すだけ）。

### 3.5 結果画面
- クリア：選んだキャラを大きく出して紙吹雪（ぽとん4・キャラたたきの勝利演出と同じ作り）。キャラは `excited` か `cheer`。「○○の かお ★20こ あつめたよ！」と、びんに入った数（「みんなの かお 46こ」）を出す。
- おしまい：キャラは `worried`＋前向きなセリフ（「もういっかい やろう！」系）。集めた数を出す。
- ボタン：「もういっかい」（同じ設定ですぐ 3・2・1）、「せっていに もどる」。

## 4. 入力

- 画面のボタン：Pointer Events で受ける。**押した瞬間（pointerdown）に1回動かす**（判断。キャラたたきと同じ理由）。左右と「ゆっくり落とす」は押しっぱなしで繰り返す（左右：押して 170ms 後から 50ms ごと。判断）。pointerup・pointercancel・ボタンから外れたら繰り返しを止める。
- 押しっぱなしの扱いはおちブロックの `ui` の中で作る（判断。core の `pointer.js` は変えない。いま必要なのはこのゲームだけ）。
- キーボード（PC）：← → で左右、↑ で回す、↓ でゆっくり落とす、スペースで一気に落とす。押しっぱなしの繰り返しはボタンと同じ間隔（OS のキーリピートには頼らない）。
- 2本の指で別のボタンを同時に押せる（例：← を押しっぱなしで ↻）。ボタンごとに pointerId を追う。
- 盤とボタンに `touch-action: none`、`user-select: none`、`-webkit-touch-callout: none`。盤そのものへのタッチは何もしない（判断。スワイプは非ゴール）。

## 5. キャラの反応と演出

### 5.1 選んだキャラ（画面の横）
- ふだんは `normal`。
- 列を消したとき（自分の操作の結果なので、喜ぶか反応なし。要件 1.6）：
  - 自分の顔が入った列を消した：`joy`・`cheer`・`love` から選ぶ＋短いセリフの吹き出し。
  - 2列以上を同時に消した：`excited`（`surprised` でもよい）＋セリフ。自分の顔が入っていても、こちらを優先する（判断。§5.3 の優先順に合わせる）。
  - 自分の顔が入っていない列だけを消した：`joy`（セリフなし）。
- 同じ表情が2回続いたら3回目は別にする（要件 1.6。キャラたたきの `reactions` と同じ作り）。
- 吹き出しは、前の吹き出しが消えるまで次を出さない（キャラたたきと同じ）。
- ブロックを置いただけでは反応しない。積み上がって危ないときも顔は変えない（§3.3 の盤のふちで知らせる）。

### 5.2 飛んでいく顔
- 列が消えるとき、その列の各マスの顔（そのキャラの `joy` の画像）がマスから飛び出し、弧を描いて「とくべつ枠」または「びん」へ入る。小さな ♪・ハート・キラを添える（どれを添えるかは実装者が決める）。
- 飛ぶ顔は Canvas ではなく、盤の上に重ねた HTML の層に置き、CSS で動かす（ユーザーが選んだ作り方。§7）。
- 飛んでいる間もゲームは止めない（判断）。ただし消えた列を詰める（上のマスが下がる）のは、顔が飛び出してから 0.25 秒後（判断。何が消えたか目で追えるように）。その間、次のブロックは出さない。
- とくべつ枠の数は、顔が枠に着いたときに1つずつ増やす（判断。集まる手ごたえ）。ただしクリア判定は列が消えた時点の数で行う。
- `prefers-reduced-motion` のとき：飛ばずにその場でふわっと消え、枠とびんの数がすぐ増える。紙吹雪・光る・揺れるは止める。

### 5.3 画面全体の演出（要件 1.6 の「1つだけ」）
- 1回の固定（ブロックが止まる）につき、画面全体の演出は1つだけ。優先順：**クリア → 4列消し → 2〜3列消し → 自分の顔を消した → 1列消し**（判断）。飛んでいく顔はどの場合も出す（画面全体の演出には数えない。マスごとのできごと）。
- 4列消しの演出は、盤全体がキラッと光る程度にする（色・形は実装者が決める）。

### 5.4 セリフ
- `games/blocks/js/lines.js` に、キャラごと・状況ごとに持つ。20文字以内、ひらがな多め、公式セリフは使わない。口調は各キャラの `voice` に合わせる。
- 状況と数：`start` 3つ以上、`mine`（自分の顔を消した）5つ以上、`multi`（2列以上）3つ以上、`almost`（残り3こ以下になった瞬間に1回）3つ以上、`clear` 3つ以上、`over`（前向き）3つ以上。
- 選び方は `core/line-picker.js`（直前と同じ行を避ける）。

### 5.5 音
- 効果音（`Ailand.core.Sound.register`）：左右に動く（小さく）、回す、固定、1列消し、2〜3列消し、4列消し、顔がとくべつ枠に入る、カウントダウン、スタート、クリア、おしまい。音色は実装者が設計する。
- BGM（`core/bgm.js`）：おちブロック用の曲を新しく1曲作る（判断。ほかの4曲と聞き分けられる曲調。`.claude/docs/specs/2026-11-12-bgm-variety-design.md` の作り方と制約に従う。既存の曲名や旋律に似せない）。残り3こ以下で `Bgm.setTempo` でテンポを上げ、終わりで止める。

## 6. 時間とループ

- `core/loop.js`（キャラたたきで作った固定間隔 1/60 秒のループ）をそのまま使う。core のループは変えない。
- 落ちる・固定までの待ち・押しっぱなしの繰り返し・列を詰めるまでの待ちは、すべて「ステップの合計時間」で数える。止めている間は進まない。
- 同じ種と同じ操作の並びなら、毎回同じ結果になる（テストの土台）。

## 7. 描画

- 盤（置いたマス・落ちてくるブロック・影）は Canvas に毎フレーム描く。`devicePixelRatio` に合わせて Canvas の実寸を決め、くっきり描く。`getImageData` 等で読み出さない（要件 1.1）。
- マスの絵：キャラの色の角丸の四角の上に、そのキャラの `normal` の画像を描く（判断）。画像は開始前に読み込んでおく。画像の読み込みに失敗したら、色の四角に顔文字（`Characters` の `face.normal`）を描く（要件 1.4 のフォールバック）。
- 飛ぶ顔・とくべつ枠・びん・キャラ・吹き出し・ボタンは HTML＋CSS。飛ぶ顔の出発位置は、Canvas の位置と1マスの大きさから計算する。
- 「つぎ」の表示も小さな Canvas でよい（実装者が決める）。

## 8. 作り（ファイル構成）

- キャラたたきと同じ形で `games/blocks/` に作る（`index.html`・`css/blocks.css`・`js/`）。`<html data-base="../../">`。
- `js/` の分け方（判断。キャラたたきにならう）：`namespace`・`constants`（盤の大きさ・難しさ表・時間）・`pieces`（7種類の形と回転。純粋）・`engine`（純粋なルール：出る順・動く・回す・固定・列消し・集めた数・クリアとおしまい。DOM なし）・`lines`・`reactions`（表情の選び方。純粋）・`controller`（流れ・一時停止・結果・保存。DOM なし）・`layout`（マスの大きさと配置）・`render`（Canvas の描画）・`fx`（飛ぶ顔・画面全体の演出）・`sounds`・`ui`（ボタン・キー・画面）・`main`。
- core の変更：`games.js` の blocks 行を `href: 'games/blocks/index.html'`・`ready: true`・`saveKey: null` にする（途中の保存がないので「つづきから」バッジは出ない）。それ以外の core は変えない（判断。必要になったら本書に追記してから変える）。
- 入口のカードの絵（いまは「じゅんびちゅう」の薄い絵）は、遊べる状態の見た目にする。
- README のゲーム一覧の状態を「遊べる」にし、内容を1行で書く。

## 9. 保存

- `Ailand.core.Storage.create('blocks')` を使う。キーは `ailand:blocks:` で始まる。
  - `settings.v1`：`{ char: id, difficulty: 'easy'|'normal'|'hard', seenHowTo: true|false }`
- 途中の状態・集めた顔・記録は保存しない。

## 10. テスト

- 自動テスト（Node、`scripts\run.bat test`。`tests/test.html` に載せる）：
  - pieces：7種類×4向きの形、回したときのずらし（左1・右1・上1の順）、どれも入らなければ回らない。
  - engine：形の出る順（7つで全種類1回ずつ）、キャラの出る順（4つで4体1回ずつ）、同じ種で同じ並び、左右の移動と壁、時間で落ちる、着いてから 0.5 秒で固定・動かすと数え直し・15回の上限、一気に落とすとすぐ固定、1列／複数列の消去と上のマスが下がる（顔とキャラがついていく）、自分の顔の数え方（消えた列のマスのうち選んだキャラのものだけ）、目標でクリア、出せないとおしまい、難しさごとの速さと下限。
  - controller：設定の保存と復元、初回だけ遊び方を出す、一時停止と再開で時間が進まない、もういっかい・せっていにもどるの流れ。
  - reactions：自分の操作の直後に `worried`・`sadness`・`anger`・`panic` を出さない、同じ表情が3回続かない、画面全体の演出の優先順。
- 静的チェック（`scripts\run.bat check`）が通ること。
- 手動テスト（ユーザーが行う）：iPhone 縦・iPhone 横・iPad 横・PC。ボタンの押しやすさと押しっぱなし、2本指（← を押しながら ↻）、自分のキャラのブロックの見分けやすさ、飛んでいく顔のかわいさ、「ふつう」が2〜3分で終わるか、「かんたん」で娘が楽しめるか。

## 11. 実装者に任せること

- 色・音色・旋律・吹き出しや飛ぶ顔の飾りの見た目・びんの絵。
- iPhone 横の配置、ボタンの並び順と大きさ（64px 以上）。
- §2.6 と §4 の数値の調整（手動テストの結果を受けて）。

## 12. 共通要件との食い違い（ユーザー合意済み 2026-11-14）

- 要件 1.8「対局中のゲームは手ごとに自動保存し、つづきから再開できる」：おちブロックは途中の再開を持たない（2026-11-14 ユーザー合意）。理由：1回が数分で終わり、落ちる速さと時間がそのまま遊びなので、途中から再開しても続きの感覚が戻らない。アプリを切り替えたときは一時停止し、同じ画面に戻れば「つづける」で続けられる。前回の設定は覚える。キャラたたきも同じ扱い（`2026-11-11-whack-design.md` §11）。

## 13. 作り方の比較（ユーザーが 1 を選んだ）

| 案 | 中身 | よい点 | 気をつける点 |
|---|---|---|---|
| 1（採用） | 盤は Canvas、飛ぶ顔・まわりの表示は HTML | 要件の「Canvas」に合う。高解像度でくっきり。共通の演出部品（`core/effects.js`・`core/reaction.js`）を使える。おちものれんさでも同じ形で使える | Canvas と HTML の位置合わせの計算が要る |
| 2 | 全部 HTML（10×20 の箱） | 顔や飛ぶ動きを CSS だけで書ける | 1/60 秒ごとに200マスを書き換え、古い iPhone でかくつくおそれ。おちものれんさの土台にならない |
| 3 | 全部 Canvas | 表示のずれが起きない | 共通の演出部品が使えず、飛ぶ動き・反応を作り直す |
