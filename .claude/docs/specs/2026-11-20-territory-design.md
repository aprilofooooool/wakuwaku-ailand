## 1. 目的

- 娘（小学校高学年）が**ママや友だち、または CPU と2〜4人で**、スキマ時間に数分で1回遊ぶ対戦。要件 §5 の「ピース陣取り」に当たる。
- 遊びの芯：**自分の色のピースを順番に盤に置いていく。自分の色どうしは角でだけつなげられる（辺ではくっつけない）。相手の行き先をふさぎながら、自分は広がる場所を残す。最後にいちばん多くのマスを置けた人の勝ち。**
- 守る体験：「ここに置けば相手の道をふさげる」と気づく楽しさと、自分の陣地がひろがる気持ちよさ。オセロっちで気に入った3点（キャラを選べる・かわいく反応する・戦況のエフェクト）（要件 §0.1）。

### 1.1 ゴール
- 1回が数分で終わる（2人で 1人12手）。
- **はじめて遊ぶ娘が、説明1画面と盤の光る点だけで「どこに置けるか」「なぜ置けないか」がわかる。**
- 「よわい」CPU に娘が勝てる（要件 §3.6 と同じ目標）。

### 1.2 やらないこと（非ゴール）
- チーム戦（2対2）。角でつながる決まりと組み合わせにくく、決まりが増えるため（ユーザー了承）。
- やさしい決まり（辺でくっついてもよい）・決まりの切りかえ（ユーザーが「本来の決まり」を選んだ）。
- 1人21個の本来のピース数・20×20 の盤（ユーザーが「1人12個」を選んだ）。
- ヒントボタン（判断。置ける角が光ることと、置けないピースが灰色になることで足りるため）。
- 全部置けたときのボーナス点などの得点の決まり（判断。「置いたマスの数」だけにして、数え方を一目でわかるようにする）。
- 時間制限・オンライン対戦。

### 1.3 アンチゴール（動いても失敗とみなすもの）
- **遊び方がわからない**：初めての娘が、どこに置けばいいか・なぜ置けないかわからないまま止まる（ピタうめっちの1回目が「ゲームが成り立たない」で不合格になったことの再発）。
- 置けるはずの場所に置けない・置いてはいけない場所に置ける・離した場所とずれた所に置かれる。
- 「よわい」CPU に娘がほとんど勝てない（要件 §0.3）。
- 置いた本人のキャラが、自分の手の直後にいやな顔をする（要件 1.6）。
- 1手で画面全体の演出が何重にも重なる（要件 1.6）。
- プレイ中に画面がスクロール・拡大・長押しメニューを出す。
- 特定の既存ゲームの名前・見た目・ピースの色の並びに似せる（要件 §5）。
- ピタうめっちの遊び方・見た目が変わる（§7.2 で core へ部品を移すため、とくに注意）。完成済みのほかのゲームの動きが変わる。

## 2. 遊び方とルール

### 2.1 盤と人数

| 人数 | 盤 | はじめのすみ |
|---|---|---|
| 2人 | 11×11 | 左上と右下（対角） |
| 3人 | 14×14 | 左上・右上・右下（左下は空いたまま） |
| 4人 | 14×14 | 4つのすみ |

- 席の順（1P・2P・3P・4P）とすみの対応：1P 左上、2P 右上（2人では右下）、3P 右下、4P 左下（判断）。手番は席順にまわる。
- 先に打つ人：2人のときは「じぶん／あいて／ランダム」、3人以上はランダム（ぽとん4と同じ）。

### 2.2 ピース（1人12個・全員同じ形）

| マス数 | 形（呼び名は内部用） | 個数 |
|---|---|---|
| 1 | 1マス | 1 |
| 2 | 2マスのぼう | 1 |
| 3 | 3マスのぼう・3マスのかぎ | 2 |
| 4 | 4マスのぼう・しかく・T・L・かいだん（S） | 5 |
| 5 | 十字（X）・長いL（L5）・かいだん5（W）（判断：形がはっきり違い、角をたくさん作れる3つ） | 3 |

- 1人の合計は 44 マス。盤のうまり具合の目安：2人 88/121、3人 132/196、4人 176/196。
- ピースはまわす（90度ずつ）・うらがえす（左右反転）ができる。

### 2.3 置き方の決まり
1. 置くピースのマスは、すべて盤の中の空いたマス。
2. **1手め**：ピースのどれかのマスが、自分のはじめのすみのマスに重なる。
3. **2手めから**：
   - ピースのどれかのマスが、すでに置いた自分の色のマスと**角（ななめ）で接する**。
   - ピースのどのマスも、自分の色のマスと**辺（上下左右）で接しない**。
   - ほかの人の色とは、辺で接してもよい。
4. 1手で置けるのは1個。置いたピースは動かせない（「1手もどす」を除く）。

### 2.4 おやすみと終わり
- 自分の番に、残りのピースをどう置いても置けないとき、その人は**おやすみ**（パス）になる。おやすみになったら、その局の終わりまでずっとおやすみ（盤は埋まっていくだけなので、置ける場所はふえない）。ピースを全部置いた人もおやすみと同じ扱い。
- おやすみは自動で判定する。その人の番は飛ばし、顔の横に「おやすみ」の札を出す（§5）。
- **全員がおやすみになったら終わり**。盤に置いたマスがいちばん多い人の勝ち。いちばん多い人が2人以上なら、その人たちの**引き分け**（判断）。
- マス数は画面に全員分ずっと出しておく（§4.4）。

### 2.5 遊び方がわかるようにする工夫（ユーザーが選んだ「本来の決まり＋置ける場所を見せる」）
- **置ける角の点**：人間の番のあいだ、盤の上に「そのプレイヤーが次にピースのマスを置ける空きマス」（1手めははじめのすみ。2手めからは自分の色と角で接し、辺で接しない空きマス）を、その人の色の光る点で出す。1手めのすみは大きめの点にする（判断）。
- **ドラッグ中の影**：ピースを盤の上で動かすと、指の位置に合わせたマスにピースの影を出す。
  - 置ける位置：その人の色でうすく塗った影。
  - 置けない位置：灰色の点線のわくだけ（判断。置けないことが見えるように）。
- **置けないで離したとき**：置き場に戻る。キャラはいやな顔をしない（要件 1.6）。盤の下に短い説明を1つ出す（判断。2秒くらい）。理由ごとに文言を分ける：
  - 自分の色と辺で接した：「じぶんの いろと へんで くっつけちゃ だめ」
  - 自分の色と角で接していない：「じぶんの いろと かどで つなげよう」
  - 1手めですみにかかっていない：「さいしょは ひかってる すみから」
  - 盤の外・ほかのピースと重なる：説明なし（見ればわかるため）
  - （文言は実装者が整えてよい。意味は変えない）
- **置けないピースは灰色**：置き場のピースのうち、いまどの向きでもどこにも置けないものは灰色にする（さわれるが、置けない）（判断）。
- **はじめの説明**：初めて開いたときだけ、遊び方を1画面で見せる。2回目からは「あそびかた」ボタンで見られる。中身（図つき。文言は実装者）：
  1. 「さいしょは じぶんの すみから おこう」（すみが光る盤の図）
  2. 「じぶんの いろとは かどで つなげるよ」（角でつながった図に○、辺でくっついた図に×）
  3. 「あいての いろとは くっついても いいよ」
  4. 「いちばん たくさん おけた ひとの かち！」

## 3. 操作

- **選ぶ**：置き場のピースをさわると、そのピースが「えらばれた」状態になる（ふちが光る）。
- **まわす・うらがえす**：ボタン（64×64px 以上）。えらばれたピースに効く。置き場のピースの絵がその向きに変わる（判断。ドラッグ前に向きを見て決められるように）。えらばれたピースがないときはボタンを押せない見た目にする。
- **置く**：置き場のピースをドラッグして盤の上で離す（ピタうめっちと同じ。ドラッグ中のピースは指の少し上に出し、盤のマスの大きさに戻す）。離した位置が置ける位置なら置かれる。置けなければ置き場に戻る（§2.5）。2本目の指は無視する。
- 置き場には**いま番の人のピースだけ**を出す（判断。iPhone で12こを大きく見せるため）。人間が2人以上のときは、番が替わると置き場もその人の色に替わる（iPhone は交代で渡す。要件 1.2）。
- **CPU の番**：置き場はうすくしてさわれない。CPU は最低 0.6 秒待ってから置く。考えている間はキャラが `thinking`＋「うーん」（要件 §3.6）。CPU が置いたピースは、置かれる前にその位置で一瞬光る（判断。どこに置いたかわかるように）。
- **1手もどす**：人間1人と CPU で遊ぶときだけ、1局で3回まで（ぽとん4 §3.8 と同じ）。人間の最後の手の直前まで戻す（その後の CPU の手も消える）。人間が2人以上のときは出さない。
- PC：マウスでも同じ（Pointer Events）。キーボード操作は作らない（判断）。

## 4. 画面と流れ

### 4.1 共通
- 共通ヘッダー（`Ailand.core.UI.header`）：「もどる」「おと」「せってい」。
- 背景の色とトーンは、ほかの6本と見分けがつく色にする（色は実装者）。見た目の土台は白いパネル・紺のふち（要件 1.9）。

### 4.2 流れ
入口 → **設定画面** → **プレイ画面** → 終わり → **けっか画面** → 「もういちど」か「せっていに もどる」。
- 途中の局があれば、設定画面に「つづきから」を出す（要件 1.8）。

### 4.3 設定画面（ぽとん4 §3.7 と同じパネル形式）
1. なんにんで あそぶ？：2人／3人／4人
2. せきと キャラ：席ごとにキャラ（重複不可）と「ひと／CPU」。既定は 1P がひと、ほかが CPU。
3. CPU の つよさ：よわい／ふつう／つよい（CPU が1人以上いるときだけ。全 CPU 共通）
4. どっちが さき？：2人のときだけ（じぶん／あいて／ランダム）
5. はじめる（途中の局があれば「つづきから」も）。「あそびかた」ボタン。
- 前回の設定を覚えておく（要件 1.8）。

### 4.4 プレイ画面
- 上に全員の顔・色・置いたマス数の札を並べる。番の人の札を目立たせる。おやすみの人は札に「おやすみ」（判断）。
- 盤（Canvas）、置き場（いま番の人のピース12こまで）、ボタン（まわす・うらがえす・1手もどす）、説明の一言の場所（§2.5）。
- iPhone 縦（390×844px）で、すべてが収まりスクロールしないこと。14×14 の盤で1マス 24px 以上（判断）。置き場は12こが並ぶこと（縮小して並べてよい）。
- iPad 横・PC：左に盤、右に札・置き場・ボタン。iPhone 横は盤を小さくしても遊べる配置にする（実装者）。
- ボタンは 64×64px 以上、本文 18px 以上（要件 1.2）。

```
iPhone 縦                              iPad 横・PC
 ← もどる                 おと ⚙       ┌──────────────────────────────────┐
 [😀12][🐱 9][🌼 7][🐰10] ← 顔とマス数  │ ┌────────────┐ [😀12][🐱9][🌼7][🐰10]│
 ┌─────────────────┐                   │ │            │  ┌──────────────┐  │
 │  14×14 の盤      │ ← 置ける角が光る   │ │  14×14 の盤 │  │ 置き場（12こ） │  │
 └─────────────────┘                   │ │            │  └──────────────┘  │
  じぶんの いろと かどで つなげよう      │ └────────────┘  [まわす][うらがえす] │
 ┌─────────────────┐                   │                  [1手もどす]        │
 │ 置き場（12こ）   │                   └──────────────────────────────────┘
 └─────────────────┘
 [ まわす ][ うらがえす ][ 1手もどす ]
```

### 4.5 けっか画面
- 勝った人のキャラを大きく出す。全員のマス数を多い順に並べる。
- 勝者に人間が1人でもいれば勝ちの演出、勝者が CPU だけなら負けの演出（要件 §3.9 と同じ考え）。引き分けは「いいしょうぶ！」。
- ボタン：「もういちど」（同じ設定ですぐ）・「せっていに もどる」。

### 4.6 一時停止・やめる
- 画面が隠れても局は進めない。CPU の番だったら戻ったときに続きを考える（判断）。
- 「もどる」：入口へ。局は自動保存されているので確認は出さない（判断。ぽとん4と同じ）。
- 「せってい」の中身：「さいしょから」（同じ設定で新しい局）と BGM の ON/OFF（判断。ほかのゲームと同じ並び）。

## 5. キャラの反応と演出

### 5.1 できごとと反応（要件 §3.9 の形にならう）

| できごと | 条件（判断） | 置いた人 | ほかの人 | 全体の演出・音 |
|---|---|---|---|---|
| place | 下のどれにも当たらない | 変化なし | 変化なし | 置いた音 |
| おおきい | 5マスのピースを置いた | joy・cheer | 変化なし | 小さなキラキラ |
| ふさいだ | 置いた結果、ほかの人の「置ける角」の数が3つ以上へった（へった人ごとに判定） | joy・smug（「とおせんぼ！」） | へった人：surprised・worried | ふさいだ音と、ふさいだ場所に小さなマーク |
| おやすみ | だれかがおやすみになった（その人の番がきて置けなかった） | — | おやすみの本人：worried・sadness（自分の手の直後ではないので要件 1.6 に反しない） | おやすみの音 |
| 終盤 | 全員の残りピースの合計が最初の4分の1以下、またはだれかが最初におやすみになった（1局1回） | 全員 thinking | 同じ | BGM のテンポが上がる |
| 勝ち | 終わって1位 | excited・cheer・love（大きく出して動かす） | sadness・worried | 紙吹雪・ファンファーレ |
| 引き分け | 終わって1位が2人以上 | joy・cheer・love | 同じ | やさしい音 |
| CPU 思考中 | CPU の番 | thinking＋「うーん」 | — | 考え中の点々 |

- 全体の演出の優先順：勝ち・引き分け → ふさいだ → おおきい → おやすみ → 終盤 → place（1手につき1つ。要件 1.6）。
- CPU と遊ぶときは、全体の演出を人間の側から見て決める（要件 1.6）。人間が置いた手が「ふさいだ」になったときは、全体の演出も人間の喜びで出す。CPU にふさがれたときは、人間のキャラの顔だけ変え、全体の演出は小さなマークだけにする（判断）。
- 同じ表情を3回続けない。人間の番に20秒操作がないと、番ではない席のキャラが sleep になる（B-3 と同じ。`core/emotion-variety.js`・`core/idle-timer.js`）。
- `prefers-reduced-motion` のときは、跳ねる・光る・紙吹雪を止め、表情と静止した表示だけにする（要件 1.3）。置ける角の点も点滅させない（判断）。

### 5.2 セリフ
- `games/territory/js/lines.js` に、キャラごと・状況ごとに3つ以上。状況：開始のあいさつ・おおきい・ふさいだ（ふさいだ側／ふさがれた側）・おやすみ・終盤・勝ち・負け・引き分け・CPU 思考中。20文字以内、ひらがな多め、公式セリフは使わない。口調は各キャラの `voice` に合わせる。選び方は `core/line-picker.js`。

### 5.3 音
- 効果音（`Ailand.core.Sound.register`、名前は `territory-` で始める）：つかむ、置いた、置き場に戻る、まわす、うらがえす、おおきい、ふさいだ、おやすみ、勝ち・負け・引き分け。音色は実装者。
- BGM（`core/bgm.js`）：ピースじんとり用の曲を新しく1曲作る。終盤でテンポが上がる。`.claude/docs/specs/2026-11-12-bgm-variety-design.md` の作り方と制約に従い、既存の曲名や旋律に似せない。

## 6. CPU

### 6.1 強さの目標（要件 §3.6 と同じ）
| 強さ | 目標 |
|---|---|
| よわい | 娘が10回中7〜8回勝てる |
| ふつう | 娘が10回中5回くらい勝てる |
| つよい | ママが本気で遊んで勝ったり負けたりする |

- 目標は **2人で遊ぶとき（子ども役 対 CPU 1人）** に合わせる。3〜4人では CPU の数に合わせた手加減をしない（ぽとん4と同じ扱い。ユーザー決定 T5）。
- 「ふつう」の1手の思考時間は 0.5 秒以内（Node 計測の最大値。4人 14×14 で測る）。
- CPU は最低 0.6 秒待ってから置く。

### 6.2 子ども役と計測（phase1 設計 §6.3 のぽとん4と同じやり方）
- 子ども役の簡易 CPU（`tests/tools/child-territory.js`、判断）：置ける手のうち、70% で「いちばん大きいピースを使う手」の中からランダム、30% で置ける手の中から完全にランダム。
- `tests/tools/measure-territory.js`：2人 11×11 で CPU 各強さと子ども役を先後入れかえて 200 局ずつ対戦させ、子ども役の勝率を出す。目標：よわい相手に 70〜80%、ふつう相手に 45〜55%。つよいは「ふつう」に 80% 以上勝つ。4人 14×14 で「ふつう」の思考時間の最大値も測る。
- 結果は `.claude/docs/reports/` に書く。
- CPU の考え方（どう手を評価するか）とパラメータは実装者。目安：自分の置けるマス数・自分の置ける角の数をふやし、相手の置ける角の数をへらし、大きいピースを早く使う。

## 7. 作り

### 7.1 ゲーム本体（`games/territory/`）
- `index.html`・`css/territory.css`・`js/`。`<html data-base="../../">`。ゲーム id は `territory`。
- 表示名：「ピースじんとり」のまま（判断。ほかの名前にしたいときはユーザーが決める）。
- `js/` の分け方（ぽとん4とピタうめっちにならう）：
  - `namespace`・`constants`（盤の大きさ・はじめのすみ・CPU のパラメータ・反応の数値）
  - `pieces`：12この形のデータ（§2.2）
  - `engine`：遊びの状態（盤・各人の残りピース・番・おやすみ）、置ける角の一覧、置けるかの判定（置けない理由つき：外・重なる・すみにかからない・辺で接する・角で接しない）、置ける手の一覧、置く、おやすみの判定、終わりと順位。純粋で DOM なし。
  - `ai`（強さごとの手の選び方。純粋）
  - `reactions`（§5.1 のできごとの判定と表情。純粋）・`lines`
  - `controller`：流れ（設定・プレイ・けっか）、手の履歴、1手もどす、保存と再開。DOM なし。
  - `layout`・`render`（Canvas：盤・置いたピース・置ける角の点・影）・`fx`・`sounds`・`ui`・`main`。
- 盤は Canvas、札・置き場・ボタン・キャラは HTML（ピタうめっちと同じ）。`devicePixelRatio` に合わせてくっきり描く。`getImageData` 等で読み出さない（要件 1.1）。
- ピースの色：席ごとに、選んだキャラのイメージ色（`Ailand.core.Characters` の `colors.main`）（判断）。同じ系統の色で見分けにくいときは、ピースのふちの線か模様で見分けられるようにする（実装者）。
- 入力は Pointer Events。盤・置き場・ボタンは `touch-action: none`。設定画面だけは縦にスクロールしてよい（ピタうめっちのずかん画面と同じ例外）。

### 7.2 core に移す部品（ユーザーが選んだ「共通の部品にする」）
- `core/piece.js`（`Ailand.core.Piece`）：`games/fill/js/piece.js` のうち形の計算 `normalize`・`rotate`（右回り）・`orient`・`same`・`place` を移し、`flip`（左右反転）と「まわす・うらがえすで作れる向きの一覧（形によって1・2・4・8通り）」を足す。ほかのファイルに頼らない。
- `core/drag.js`（`Ailand.core.Drag`）：`games/fill/js/drag.js` をそのまま移す（1本の指だけ追う・pointer capture・`pick/onStart/onMove/onEnd/onCancel`）。
- ピタうめっちに残すもの：`fits`・`distancesFrom`・`partition`（枠と分け方はピタうめっちだけの決まり）。`games/fill/js/piece.js` はこれだけを持ち、形の計算は `Ailand.core.Piece` を使う。`games/fill/js/drag.js` は消し、`Ailand.core.Drag` を使う。
- テスト：形の計算とドラッグのテストを `tests/core/` へ移す。ピタうめっちのテストは、残る部分を `tests/fill/` に残し、**移す前と同じ数・同じ中身の確かめが全部通る**こと。
- `games/fill/index.html`・`tests/test.html` の `<script>` の並びを直す。
- ピタうめっちの見た目・動き・保存は変えない。

### 7.3 そのほかの core と文書の変更
- `core/games.js` の territory 行：`href: 'games/territory/index.html'`・`ready: true`・`saveKey: 'ailand:territory:save.v1'`。`tests/core/games.test.js` を合わせる。
- 入口のカードの絵は遊べる状態の見た目にする（実装者）。

- これ以外の core は変えない（必要になったら本書に追記してから変える）。

## 8. 保存

- `Ailand.core.Storage.create('territory')`。キーは `ailand:territory:` で始まる。
  - `settings.v1`：人数・席ごとのキャラと「ひと／CPU」・CPU の強さ・先手・`seenHowTo`。読めない値は既定（2人・1P ひと／2P CPU・よわい・ランダム・false）。
  - `save.v1`：途中の局（設定と手の履歴、1手もどすの残り回数）。手ごとに保存し、終わったら消す。読めない・決まりに合わない履歴は捨てて新しい局にする（判断）。
