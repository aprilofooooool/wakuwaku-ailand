# キャラの反応バリエーション追加 設計

- 日付：2026-11-12
- 対象：ぽとん4（`games/drop4/`）、オセロっち（`games/othello/`）、キャラたたき（`games/whack/`）、`core/`
- 状態：ユーザー承認済み（2026-11-12）
- 進め方：ユーザーから「特に不満はないので、おすすめで」と指示があった（2026-11-12）。このため、本書の中身はすべて Claude の判断で、ユーザーには承認だけをもらう。

## 1. 目的（なぜ）

- 2026-11-12 に4体ぶんの新しい表情画像7種（worried・surprised・excited・sleep・smug・cheer・love）が入った。でも、いまのゲームでは同じ場面にいつも同じ表情が出ていて、新しい画像の多くが使われていない。
- 要件書 §0.1 の「選んだキャラがかわいく反応する（表情とセリフ）」を強めるのが目的。何回遊んでも、同じ場面で少しずつ違う顔を見られるようにする。

## 2. ゴール・やらないこと・失敗とみなすこと

ゴール
- 3ゲームとも、主な場面で表情を2〜3種類から選んで出す。
- 新しい7表情のうち、`sleep` と `surprised`・`worried`・`smug`・`cheer`・`love`・`excited` をそれぞれ少なくとも1つのゲームで使う。
- 「待ちくたびれて ねむる」反応を、ぽとん4とオセロっちに足す（`sleep` の使いみち）。
- キャラたたきに「れんぞく」の反応を足す。

やらないこと
- 画面全体の演出（紙吹雪・盾・キラキラなど）や音を増やすこと。演出の種類と出る条件は今のまま。
- オセロっちの対局の進み方（`games/othello/js/game/` と `engine/`）を変えること。表情の選び直しは画面側（`ui/`）だけで行う。
- `tests/golden/othello-replay.json` を作り直すこと。
- 画像の追加・作り直し。

失敗とみなすこと（要件書 §0.3・§1.6 と同じ）
- 手を打った本人のキャラが、自分の手の直後にいやな顔（anger・sadness・panic・worried・surprised）をする。
- 負けた側のキャラが、終わりの画面で sadness・worried 以外のいやな顔（anger・panic など）をする。
- 1手に画面全体の演出が2つ以上出る。
- 同じキャラに同じ表情が3回続く（選べる候補が2つ以上ある場面で）。
- `scripts\run.bat replay-othello` が golden と合わなくなる。
- 旧オセロっちの保存データ（`otc.*`）にふれる。

## 3. 共通の部品（core）

### 3.1 `core/emotion-variety.js`（新設）

- `Ailand.core.EmotionVariety.create(rng)` が `{ pick(key, pool), reset() }` を返す。
- `pick(key, pool)`：`pool`（表情名の配列）から1つを `rng` で選ぶ。`key`（キャラや席ごとの見分け用の文字列）ごとに直前2回の表情を覚え、その2回が同じなら、その表情を候補から外して選ぶ。`pool` が1つだけならそれを返す（3回続いてもよい）。
- `reset()`：覚えている履歴を消す（新しい対局の開始時に呼ぶ）。
- 理由：3ゲームで同じ「候補から選び、3回続けない」処理を使うため、core に1つだけ置く。キャラたたき `js/reactions.js` の中にある同じ処理はこれに置き換える（動きは変えない）。

### 3.2 読み替え表

- `core/emotion-map.js` は変えない（13表情すべて手持ち画像がある）。

## 4. ぽとん4

### 4.1 場面ごとの表情の候補

`js/reactions.js` の `detect` が出す各できごとの表情を、下の表の候補から選び直す。いまの表情は候補の先頭に置く。

| できごと | 打った人（同じチーム含まず本人） | ほかの人 |
|---|---|---|
| リーチ | joy・cheer | worried・surprised |
| ダブルリーチ | excited・cheer | surprised・panic |
| ブロック | joy・smug（ドヤ顔で「とめた！」） | 止められた人：anger・surprised |
| 終盤 | 全員 thinking（今のまま） | 同じ |
| 勝利 | 勝った人：excited・cheer・love | 負けた人：sadness・worried（下の 4.3） |
| 引き分け | 全員 joy・cheer・love | 同じ |
| CPU 思考中 | thinking（今のまま） | — |

- 選び直しは controller が `detect` の直後に行い、`reaction` イベントに載せる表情を選び直したものにする（Claude の判断：`detect` は決まった表情を返すままにして、今のテストを壊さない）。
- 候補表は `js/reactions.js` に `POOLS`（`'<できごと>:<mover|other>'` → 表情の配列）として置く。
- 履歴の key は席番号。対局の開始・「さいしょから」で `reset()` する。「まった（undo）」では消さない。
- 乱数は controller がもらっている `rng` を使う（テストで種を固定できる）。

### 4.2 勝利の大きな表示

- `js/fx.js` の勝利の大きな表示は、いま `joy` 固定。これを、その勝った人の `win` できごとで選ばれた表情にする。

### 4.3 負けた人の顔

- いまは負けた人が `sadness` 固定、CPU だけが勝ったときの大きな表示も `sadness` 固定。これを `sadness`・`worried` から選ぶ形に変える（2026-11-12 ユーザー指定）。大きな表示は、その人の `lose` できごとで選ばれた表情を使う。表示の文「おしかった！ つぎは がんばろう！」とセリフはそのまま。
- ぬきとりで相手の4つをそろえてしまった本人（今は `normal`）は `normal` のまま（打った本人にいやな顔をさせない）。
- これに合わせて要件書 §3.9 の表の「勝利／ほかの人：sadness」と §3.9 末尾の「人間キャラは sadness」を「sadness か worried」に直す。

### 4.4 待ちくたびれ（sleep）

- 人間の番で、最後の操作（盤へのタッチ・マウス移動・キー入力）から **20秒** 何もないと、その番ではない席のキャラ（CPU・ほかの人間とも）が `sleep` の顔になり、吹き出しに `sleep` のセリフを1回出す。
- 番の人が何か操作するか、手を打つと、ねむっていたキャラは `normal` に戻り、吹き出しを消す。そのあとの反応は今までどおり。
- 1回の番でねむるのは1回だけ。勝負が終わっている間・設定画面では数えない。
- ぽとん4には今は一時停止の仕組みがないので、新しく `visibilitychange` を見る。タブが隠れたら数えるのを止め、見えるようになったら0から数え直す（Claude の判断：隠れている間にねむらせないため）。
- 画面全体の演出も音もない（顔と吹き出しだけ）。
- 20秒は `js/constants.js` に `SLEEP_AFTER_MS` として置く。

### 4.5 セリフ

- `js/lines.js` の各キャラに `sleep` を3つずつ足す（20文字以内・ひらがな多め・口調は今のセリフに合わせる）。例：まめっち「すこし ねむくなってきました…」。
- 新しい表情（cheer・smug など）には新しい状況名を作らない。セリフはいまの状況名（reach・block など）のものを使う。

## 5. オセロっち

### 5.1 守ること

- `game/`（controller・reaction-engine・move-reaction）と `engine/` は1行も変えない。controller の `rng` を使う呼び出しの数も変えない。理由：`replay-othello` の golden は controller が出す `emotion` イベントと手の並びを記録していて、作り直さない約束（`2026-11-09-othello-core-migration-design.md` §2）のため。
- 新しい表情は、画面側（`ui/ui-manager.js`）が `emotion` イベントを受けて **アバターに出す画像だけ** を選び直すことで出す。どの全体演出を出すか（`pickEffect`）は controller が出した元の表情で決まるので、変わらない。
- 画面側の選び直しには、controller とは別の乱数（`Math.random`）を使う。

### 5.2 表示の選び直し

| controller が出す表情 | 対局中にアバターに出す候補 | 終局時 |
|---|---|---|
| joy | joy・excited・cheer | 勝った人：excited・cheer・love |
| panic | panic・surprised・worried | — |
| sadness | sadness・worried | 負けた人：sadness・worried（下の 5.3） |
| anger | anger（今のまま） | — |
| normal・thinking | 今のまま | 引き分け：normal（今のまま） |

- 画面側は表情の名前しか受け取らないので、選び直しは表情の名前だけで決める（どの理由で出た表情かは見分けない）。joy は打った本人にしか出ないので、本人にいやな顔は出ない。

- 「終局時」は、controller が終局で出す `emotion`（`game-controller.js` の2人戦 約423行・4人戦 約348行）を指す。画面側は、勝負が終わった印（`over` 系のイベントや view の終局フラグ。どれを使うかは builder が今のコードから決める）で終局を見分ける。
- 3回続けない決まり（§3.1）をアバターごとに使う。key は席（`p1`〜`p4`）。新しい対局の開始で `reset()`。

### 5.3 負けた人の顔

- 終局時に controller が負けた人へ出す `sadness` を、画面では `sadness`・`worried` から選んで表示する（2026-11-12 ユーザー指定）。controller の出す値は変えないので golden は変わらない。

### 5.4 表情の印（新設）

- ぽとん4・キャラたたきと同じように、オセロっちのキャラ枠（パネル）にも表情の印を出す（2026-11-12 ユーザー指定）。
- 各パネルに印を置く要素を1つ足し、アバターの表情を変えるたび（`setAvatar`）に `Ailand.core.Effects.mark(印の要素, Ailand.core.CharacterView.markOf(表情))` を呼ぶ。印の見た目と出し方は core の `Effects.mark` にまかせる（ぽとん4と同じ）。
- いまの読み替え表では印を持つ表情は `angry-steam` だけで、オセロっちはこれを使わない。このため、実際に印が出るのは §5.5 の `sleep`（💤）から。読み替え表に印が増えれば、オセロっちにも自動で出る。
- 印の位置と大きさは、ぽとん4の席の印に見た目をそろえる（細かい位置は builder が決める）。

### 5.5 待ちくたびれ（sleep）

- ぽとん4の §4.4 と同じ決まりを、画面側だけで作る（20秒、番ではない席のキャラが `sleep`、操作か着手で `normal` に戻る）。定数は `config/constants.js` に `SLEEP_AFTER_MS: 20000` を足す（controller は使わない）。
- 吹き出しのセリフは、画面側が自分の LinePicker（`Math.random`）で `O.Lines[キャラ].sleep` から選ぶ。controller の `say` は使わない。
- `data/lines.js` の各キャラに `sleep` を3つずつ足す。`O.SITUATIONS` にも `sleep` を足す（各キャラ3つ以上の検査に入れるため）。既存の状況のセリフは1文字も変えない。

## 6. キャラたたき

### 6.1 タッチの反応

| 種類 | いま | 変更後 |
|---|---|---|
| じぶんのキャラ | joy・excited・cheer・love（今のまま） | 今のまま |
| キラカード | excited 固定 | excited・surprised（surprised は 2026-11-12 に本物の「びっくり」画像が入ったので使える。2026-11-11 に外した理由の「あわて顔への読み替え」はもうない） |
| さわっちゃダメ | smug | 今のまま |

- じぶんのキャラの反応で「3回続けない」は §3.1 の core 部品に置き換える（動きは同じ）。

### 6.2 れんぞく

- 1人ぶんの1回のプレイで、ダメのキャラにさわらずに、じぶんのキャラ（キラカード含む）を **5回つづけて** タッチしたら、5回目の反応を `cheer` ＋ キラの飾り ＋ `combo` のセリフにする。続ければ10回目・15回目…も同じ。ダメにさわると数え直し。
- キラカードが5回目に当たったときは、キラカードの反応（§6.1）を優先し、`combo` は出さない（全体の演出を重ねない）。
- 見逃し（タッチせずに引っこんだ）では数え直さない（Claude の判断：子どもが続けやすいように）。
- 「キラの飾り」は、ふつうのタッチと同じ飾り（deco の `sparkle`）だけ。キラカード用のキラキラの粒（`Fx.sparkleAt`）は出さない（Claude の判断：演出を増やさないため）。
- 音・画面全体の演出は増やさない。

### 6.3 結果画面

| 場面 | いま | 変更後 |
|---|---|---|
| 1人・新記録 | excited | excited・cheer・love |
| 1人・新記録でない | joy | joy・cheer |
| 2人・勝った人 | excited | excited・cheer・love |
| 2人・負けた人 | joy | sadness・worried（2026-11-12 ユーザー指定。セリフは今の前向きな `lose` のまま） |
| 2人・同点 | 2人とも joy | joy・love（それぞれ選ぶ） |

- 1人で遊んで新記録でないときは「負け」ではないので、今までどおり明るい顔（joy・cheer）にする。
- これに合わせてキャラたたき設計書 `2026-11-11-whack-design.md` §3.5 の「負けた側のキャラは `joy`」と §2 の失敗条件「負けた側のキャラがいやな顔をする」を書き直す（本書を参照する1行を足す）。

### 6.4 セリフ

- `js/lines.js` の各キャラに `combo` を3つずつ足す。例：くちぱっち「れんぞくだっち！すごいだっち」。

## 7. テスト

- 自動テスト（`scripts\run.bat test`）
  - `EmotionVariety`：候補から選ぶ・同じ表情が3回続かない・候補が1つなら同じものを返す・`reset()` で履歴が消える。
  - ぽとん4：`POOLS` の「打った人」の候補にいやな表情（anger・sadness・panic・worried・surprised）が入っていない・各できごとで選ばれた表情が候補の中にある・負けた人が `sadness` か `worried`・勝利と負けの大きな表示が選ばれた表情を使う・待ちくたびれのタイマー（偽の時計で20秒・操作で戻る・1番に1回）。
  - オセロっち：表示の選び直しの表どおりに選ぶ・終局で負けた人が `sadness` か `worried` の表示・パネルに印の要素があり `sleep` で 💤 が出る・待ちくたびれ。
  - キャラたたき：れんぞく5回で cheer＋combo・ダメで数え直し・キラカードが優先・結果画面の候補（2人の負けた人が `sadness` か `worried`）。
  - セリフ：新しい `sleep`・`combo` が各キャラ3つ以上・20文字以内（今のセリフ検査に足す）。
- `scripts\run.bat check`（静的チェック）。
- `scripts\run.bat replay-othello`（約3.5分、background で実行）が golden と一致すること。
- GUI の手動テストはユーザーが行う（表情の見え方・ねむる20秒・れんぞく）。

## 8. builder に任せること

- 新しいセリフの文面（口調は各ゲームの今のセリフに合わせる。20文字以内・ひらがな多め・公式のセリフは使わない）。
- 待ちくたびれのタイマーを置く場所と、「操作」として数えるイベントの細かい選び方。
- オセロっちで終局を見分ける方法（§5.2）。
- `sleep` の顔のときに印 `zzz`（💤）を付ける方法。読み替え表（`core/emotion-map.js`）の `sleep` の行の mark を `zzz` にすれば、ぽとん4・オセロっちとも `markOf` 経由で自動で出る。この方法を第一候補とする（要件書 §1.5 の表も合わせて直す）。

## 9. 決めたことの一覧

ユーザーが決めたこと（2026-11-12）
- 負けた側のキャラは、3ゲームとも `sadness`・`worried` から乱数で選ぶ（キャラたたきは2人で負けたとき）。
- オセロっちにも、ほかのゲームと同じ表情の印の仕組みを足す。

Claude の判断（ユーザー確認用）
1. ブロックした本人に `smug`（ドヤ顔）を使う。
2. 印 `zzz` は読み替え表の `sleep` の行に付ける（§8）。
3. 待ちくたびれの時間は20秒。
4. キャラたたきのキラカードに `surprised` を足す（本物のびっくり画像が入ったため）。
5. れんぞくは5回ごと。見逃しでは数え直さない。
6. オセロっちは画面に出す顔だけを選び直し、対局の進み方は変えない。
