# おちブロック 追加設計：時間の制限とほしブロック

元の設計：`.claude/docs/specs/2026-11-14-blocks-design.md`（以下「元設計」）。この文書は元設計への追加と変更だけを書く。書いていないことは元設計のまま。

## 1. 目的

- 手動テストで「動作は問題ないが、ゲーム性が低い」となった（ユーザー、2026-11-14）。
- 白熱・ハラハラ・わくわくする要素を足す。ユーザーが選んだのは次の3つ。
  - 時間の制限
  - 一発逆転の大きなごほうび
  - 「むずかしい」の必要数を上げる
- 非ゴール：
  - 設定画面に新しい選択肢を足さない。
  - 相手からの邪魔は足さない。
  - 保存しない（元設計 §9 のまま）。
- アンチゴール：
  - 娘さんが遊ぶ「かんたん」で、時間切れの負けばかり続く。
  - 1回が長くなる（元設計のアンチゴールと同じ）。

## 2. ルールの追加

### 2.1 時間の制限（ユーザー選択：A ＝ 時間切れで負け）

- 残り時間を持つ。カウントダウン中と一時停止中は減らない（減らすのはプレイ中の時間だけ）。
- 自分の顔を1つ消すごとに、残り時間が延びる。
- 残り時間が 0 になったら「おしまい」（負け）。元設計 §2.5 の負けと同じ結果画面を出し、時間切れのセリフを足す。困った顔（`worried`）まで。
- 列を消している演出中（settling）に 0 になった場合：その消しでゴールに届いていればクリアを優先する（判断。届いた瞬間に勝ちとみなすほうが子どもに分かりやすいため）。

### 2.2 ほしブロック（ユーザー選択：B）

- 12〜18個に1回、ほしブロックが来る（何個目に来るかは、その範囲でランダム）。
- ブロックの4マスのうち1マスに金色の星が付く。顔は付いたまま。「つぎ」の枠でも星が見える。
- 星の付いたマスを含む列を消したときの動き：
  1. 列消しのあと、盤の上に残っている自分の顔のマスがすべて飛んでいく。数はゴールに入り、時間の延長も1つごとに付く。
  2. 時間がさらに +15秒 延びる。
  3. 飛んだ顔のマスは空きになり、**その上のマスが列ごとに下へ落ちる**（ユーザー選択）。
  4. 落ちた結果、新しく横1列そろったら、続けて消す（判断。わくわくを足すため。連続で消したときも通常の列消しと同じ扱い）。
- 星を消さずに積んだ場合：星はそのマスに残る。その列を消せば効く。
- 1回の消しに星が2つ入っても、効果は1回分（判断）。

### 2.3 数の目安（`constants.js` にまとめる。手動テストで調整する前提）

| 項目 | かんたん | ふつう | むずかしい |
|---|---|---|---|
| 目標の数 | 15こ（ユーザー） | 30こ（ユーザー） | 50こ（ユーザー） |
| 制限時間 | 180秒 | 150秒 | 120秒 |
| 自分の顔1つで延びる時間 | +3秒 | +3秒 | +2秒 |
| ほしで延びる時間 | +15秒 | +15秒 | +15秒 |
| ほしが来る間隔 | 12〜18個 | 12〜18個 | 12〜18個 |

- 落ちる速さ・速くなる倍率・下限は、元設計 §2.6 のまま。
- 制限時間と延びる時間は判断（ユーザーは「手動テストで調整」で了承）。

## 3. 画面・音の追加

- 画面上部に残り時間（「のこり 2:30」のような形）を出す。
- 時間が延びたら、時計のそばに「+6」のように一瞬出す。
- 残り10秒になったら：
  - 時計を赤くして点滅させる。
  - 1秒ごとにチクタク音を鳴らす。
  - 曲を速くする。「もうすこし」で速くなる場合と重なったら、速いほうに合わせる。
- ほしの列を消したら：
  - 画面全体を光らせる演出（元設計 §5.3 の「1つだけ」の枠を使う）。
  - ファンファーレを鳴らす。
  - 選んだキャラが専用のセリフを言う。
  - 盤じゅうの自分の顔が一斉に飛ぶ。

## 4. 作り方

- 時間はゲームのループが動く間だけ進む（`ui.js:4`）。そこで、残り時間とほしの判定は `engine.js` の状態と `step(ms)` に持たせる。こうすると、一時停止の扱いを新しく作らずに済み、Node のテストで確かめられる。
- `ui.js` / `fx.js` / `sounds.js` / `render.js` は、engine のイベントと状態を見て表示するだけにする。
- engine に足すイベント：
  - `time`（延びた秒数）
  - `star`（飛んだ顔の数）
  - `timeup`（時間切れ。状態は `over`、理由で区別する）
- ほか2案を取らない理由：
  - 時間を `ui.js` に持たせる案：テストできない。一時停止と二重に管理することになる。
  - 別ファイルに分ける案：engine の列消しと強く絡むので、分けると境目が増えるだけ。

## 5. テストで確かめること

- 時間が step でだけ減ること。0 で `over`（理由は時間切れ）になること。
- 自分の顔を消すと延びること。
- ほしの出る間隔が 12〜18 の範囲に入ること。
- ほしの列を消すと、盤上の自分の顔がすべて消えて数に入り、上のマスが列ごとに落ちること。そのあと連続で消えること。
- 消しでゴールに届いたら、時間切れより勝ちが優先されること。
- 難しさごとの数が上の表どおりであること。

## 6. 実装者に任せること

- 時計・星・「+6」の見た目、チクタク音とファンファーレの音色。
- ほしの列消しの演出の細かい時間（元設計の SETTLE_MS を基準に長めにしてよい）。
- 時間切れ・ほしのセリフの文言。元設計 §5.4 の言葉の決まりに従う。
