# おちブロック 追加設計：きろくチャレンジとボタンの並び

- 作成日：2026-11-14
- 状態：ユーザー承認済み（2026-11-14）
- 元の設計：`.claude/docs/specs/2026-11-14-blocks-design.md`（以下「元設計」）、`.claude/docs/specs/2026-11-14-blocks-thrill-design.md`（以下「追加設計1」）。この文書は両者への追加と変更だけを書く。書いていないことは両者のまま。
- 表記：「（判断）」は本書作成者が決めた点。ユーザーが決めた点には付けない。

## 1. 目的

- ユーザーが**時間に余裕があるときに、自分の記録を塗り替えたくて挑戦する**遊び方を足す（ユーザー、2026-11-14）。
- あわせて、スマホの操作ボタンの並びを変える（ユーザー指定）。
- 非ゴール：
  - 家族で点を比べる仕組み（ランキング・名前の入力）。
  - キャラごとの記録。
  - 途中から続きを遊ぶための保存（元設計 §12 のまま）。
- アンチゴール：
  - 今の「かおあつめ」の遊び心地が変わる（時間・目標・ほし・演出は追加設計1のまま）。
  - 記録が消える・おかしな値で残る。

### 1.1 元設計の非ゴールの変更

- 元設計 §1.2 の「最高記録」「点数」をやらない、は**きろくチャレンジでは取り消す**（ユーザー、2026-11-14）。かおあつめでは記録を持たないまま。

## 2. ボタンの並び（両方の遊び方）

- 縦向き（1列）：左から **← ・↓（早く下ろす）・いっきにおとす・↻（回す）・→**（ユーザー指定）。
- 横向き・PC（盤の左右に分かれる配置）：左に **← ↓ いっきにおとす**、右に **↻ →**（判断。縦の並びを左右に割っただけにして、指の位置を覚え直さずに済むようにする）。
- キーボードの割り当て（元設計 §4）は変えない。

## 3. きろくチャレンジのルール

### 3.1 点数と終わり方

- 点数＝消した列に入っていた**自分のキャラの顔の数**（ユーザー選択 A）。ほしで集めた顔も入る。ほかのキャラの顔はびんに入るだけで点にならない（かおあつめと同じ）。
- 目標の数はない。時間の制限もない（時計を進めない、時間切れもない）。
- 終わるのは、ブロックが上まで積み上がって次が出られないとき（元設計 §2.5 の「おしまい」）だけ。
- 落ちる速さ・速くなる倍率・下限は、元設計 §2.6 の難しさの表のまま（判断）。上手な人は下限の速さで長く続けられるが、それは受け入れる。長すぎると感じたら手動テストで、きろくチャレンジだけの下限を足すかを決める。
- ほしブロック（追加設計1 §2.2）は同じように来て、同じように盤の自分の顔を集める。**時間は延びない**（顔1つの延長も、ほしの +15秒 も付けない）。

### 3.2 最高記録

- 難しさごとに1つ持つ（判断。キャラたたきと同じ形）。保存のキーと形はキャラたたきにならう：`best.v1` に `{ easy: n, normal: n, hard: n }`。
- 読めない・数でない・0以下の値は「記録なし（0）」として扱う。
- 点数が記録より大きく、かつ 1 以上なら「しんきろく」。保存は**プレイ中、点数が保存済みの記録を超えるたびにその場で書く**（判断。終わりがないので途中でやめる人が多い。もどる・せってい・アプリを閉じる、のどれでやめても塗り替えた記録が消えないようにする）。
- 結果画面とプレイ中の比べる相手は、**始めたときの記録**（判断）。途中で保存した値とは比べない。
- 初めての1回（始めたときの記録が 0）は、1 以上なら結果画面で「しんきろく！」を出す（判断。キャラたたきと同じ）。プレイ中の演出（§3.3）は出さない。
- 結果画面が出ずにやめた回は、結果画面を出さない（今のまま）。記録だけ残る。

### 3.3 プレイ中の盛り上がり（判断。記録を塗り替える楽しさの見せ場）

- **もうすこし**：記録まで残り 1〜3 個になった最初の1回だけ、かおあつめの「もうすこし」と同じ演出（曲が速くなる、セリフ）を出す。記録がない（0）ときは出さない。記録に一気に届いた／超えたときは出さずに使い切る（かおあつめと同じ考え方）。
- **しんきろく！**：点数が記録を初めて超えた瞬間に1回だけ、「しんきろく！」の文字・音・選んだキャラのセリフと表情を出す。記録がない（0）ときは出さない。画面全体の演出は元設計 §5.3 の「1つだけ」の枠に従う（ほしと重なったら、文字と音はほしを優先し、セリフはしんきろくにする）。
- 1回の列消しやほしで、記録までの残りを飛び越して一気に超えたとき：もうすこしは出さずに使い切り、しんきろくだけ出す（判断）。同じ消しで両方の条件に当たったときも、しんきろくだけ出す。イベントの順は `clear`／`star` のあとに `record`（判断）。
- 「もうすこし」で速くなった曲は、そのまま終わりまで速いまま（判断。記録を超えたあとも盛り上がりを保つ）。

## 4. 画面

### 4.1 設定画面（元設計 §3.2）

- 「あそびかた」の欄を足す：**かおあつめ／きろくチャレンジ**。前回の選択を覚える（`settings.v1` に `mode` を足す。値は `collect` / `challenge`。読めない値は `collect`）。
- 難しさの説明：かおあつめは今のまま（「15こ あつめよう／3ぷん」）。きろくチャレンジは「さいこう 23こ」、記録がなければ「きろく なし」。

### 4.2 遊び方の画面

- 選んだ遊び方に合わせて説明の文を変える。きろくチャレンジは「じかんは ない」「うえまで つまったら おしまい」「さいこうきろくを こえよう」の内容を含める（文言は元設計 §5.4 の言葉の決まりに従い実装者が決める）。

### 4.3 プレイ画面

- 時計（追加設計1 §3）は出さない。のこり10秒の演出も起きない。
- 「★ 12／15」は「★ 12」にし、その近くに「さいこう 23」を出す（始めたときの記録が 0 なら、その回のあいだずっと出さない）。しんきろくのあとは「さいこう」の数を今の点数に合わせて増やしていく（判断）。

### 4.4 結果画面（元設計 §3.5）

- 「おしまい」の文字、「★ 25こ あつめたよ」、「さいこう 25」を出す。
- しんきろくのとき：「しんきろく！」の文字、クリアの音（`blocks-goal`）、うれしい表情とセリフ。
- しんきろくでないとき：今の「おしまい」の音・表情・セリフ。
- 「もういっかい」は同じ遊び方・難しさで始める。

## 5. 作り方（ユーザー承認）

- `engine.js` の `create` に遊び方（`mode`）と今の記録（`best`）を渡す。きろくチャレンジでは目標・時間・時間の延長の処理を通さない。記録を超えた瞬間を新しいイベント `record` で知らせる。もうすこしは記録までの残りで判定する。
- `controller.js` が設定の `mode` と最高記録の読み書きを持つ（キャラたたきの `bestOf` と同じ形）。結果に `mode`・`best`・`newRecord` を足す。
- `ui.js` / `fx.js` / `sounds.js` / `lines.js` / `reactions.js` は、イベントと状態を見て表示するだけ。
- 取らない案：
  - 別のゲームファイルとして作る：列消し・ほし・速さを二重に持ち、直すときに2か所を直すことになる。
  - 見た目の側で目標と時間を大きくするだけ：時計やもうすこしが変に出て、積み上がりだけで終わる決まりをきれいに作れない。

## 6. テストで確かめること

- きろくチャレンジでは、step で時間が減らず、時間切れにならない。列を消しても時間が延びない。ゴールにならない。
- 積み上がったときだけ `over`（理由は `blocked`）になる。
- ほしで集めた顔が点数に入り、時間は延びない。
- `record` は記録を初めて超えたときに1回だけ出る。記録 0 のときは出ない。
- もうすこしは記録まで残り 1〜3 で1回だけ出る。記録 0 のときと一気に超えたときは出ない。
- 最高記録が難しさごとに保存され、読めない値は 0 になる。記録以下では保存しない。記録を超えた時点で（結果を待たずに）保存され、途中でやめても残る。
- 初めての1回（記録 0）で 1 以上なら、結果の `newRecord` が true になる。
- 設定の `mode` が保存・復元され、読めない値は `collect` になる。
- かおあつめの動きが変わっていない（今のテストがそのまま通る）。
- ボタンが縦向きで ← ↓ いっきにおとす ↻ → の順に並ぶ。

## 7. 実装者に任せること

- 「あそびかた」欄・「さいこう」表示・「しんきろく！」の見た目と音色。
- しんきろく・記録が近いときのセリフの文言（元設計 §5.4 に従う。かおあつめの「もうすこし」のセリフが「クリア」を含むなら、きろくチャレンジ用に別の文を用意する）。
