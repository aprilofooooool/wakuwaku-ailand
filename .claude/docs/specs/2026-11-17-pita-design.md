# ピタうめっち（fill）設計書

- 作成日：2026-11-17
- 状態：ユーザー承認済み（2026-11-17）
- 位置づけ：ピタうめっちの仕様の正。あいランド共通の要件は `.claude/docs/specs/2026-11-08-ailand-requirements.md`（以下「要件」）、フォルダ構成・テストの約束は `.claude/docs/specs/2026-11-08-ailand-phase1-design.md` に従う。作りの見本はぷにっち（`.claude/docs/specs/2026-11-15-puni-design.md`・`games/chain/`）。
- 表記：「（判断）」は本書作成者が決めた点。ユーザーが決めた点には付けない。

## 1. 目的

- 娘（小学校高学年）が**ひとりでスキマ時間に数分で1回遊ぶ**ためのパズル。要件 §5 の「ピース埋め」に当たる。
- 遊びの芯：**絵の形をした枠を、いろいろな形のピースでぴったり埋める。埋め終わると枠がかわいいドット絵に変わり、「ずかん」に貼られる。** ずかんを全部埋めるのが長い目当て。
- 守る体験：「ぴたっ」とはまる気持ちよさと、完成した瞬間に「こんな絵だったのか！」とわかる驚き。急かさず、じっくり考えられる。

### 1.1 ゴール
- 1まいが1〜3分で終わる。
- ずかんで「あと ○まい」が見え、次の絵を遊びたくなる。
- 詰まっても、ヒントで1人で先に進める。

### 1.2 やらないこと（非ゴール）
- 時間制限・点数・タイム記録。じっくり考える遊びなので急かさない。
- 絵を毎回自動で作ること（試作で「かわいくない」と判断され、やめた）。
- キャラ（まめっち等4体）の絵をずかんに入れること（ユーザーが用意を試みたが、ドット絵の質がそろわず見送り）。
- 2人以上で遊ぶこと。対戦（ピースじんとりで扱う）。
- 途中からの再開（つづきから）。§11。
- 解き方が1通りかどうかの保証。どんな並べ方でも全部埋まればクリア。

### 1.3 アンチゴール（動いても失敗とみなすもの）
- 解けない問題が出る。
- 完成した絵が崩れていて、何の絵かわからない。
- 特定の既存ゲーム・作品の名前・キャラ・見た目に似せる（要件 §5）。
- ピースをつかんだつもりが動かない・離した場所とずれた所に置かれる・置けるはずの所に置けない。
- 自分の操作の直後に、選んだキャラがいやな顔をする（要件 1.6）。
- 1回の操作で画面全体の演出が何重にも重なる（要件 1.6）。
- プレイ中に画面がスクロール・拡大・長押しメニューを出す。
- 完成済みのほかのゲーム（`games/` の既存5本）の動きが変わる。

## 2. 遊び方とルール

### 2.1 絵と枠
- 1まいの絵は「1マス＝4×4ドット」のドット絵（§6）。
- **枠**＝絵を4×4ドットごとに区切ったとき、色のあるドットが1つでもある区画（マス）の集まり。枠のマスは上下左右で1つにつながっている。
- 盤に描くのは枠のマスだけ（点線のマス）。遊んでいる間、絵は見せない。

### 2.2 ピースと問題の作り方
- ピースは、正方形のマスを上下左右でつなげた形（ポリオミノ）。1つのピースは **4〜5マス**（判断。3マス以下は簡単すぎ、6マスは形がわかりにくい）。
- 問題は **枠をランダムにピースへ分けて** 作る。分けた結果が「答えの一例」。分けてから作るので、必ず解ける。
- 分け方は、遊ぶたびに乱数の種を変えて変える（同じ絵でも毎回ちがう問題）。乱数は `core/rng.js` の種つき乱数。同じ種なら同じ分け方。
- 分け方の決まり：すべてのマスがどれか1つのピースに入る。どのピースも上下左右でつながっている。どのピースも4〜5マス。条件を満たす分け方が見つかるまで種を変えてやり直す（やり直しの上限と、上限に達したときの扱いは実装者。ただし「解けない問題を出さない」は必ず守る。テストで全部の絵について確かめる）。
- ピースの数は枠のマス数で決まる（目安は §2.6）。
- ピース置き場に並べるときの向きは、ピースごとに乱数で回転・裏返しを決める（判断。答えの向きのまま並ぶと簡単すぎるため）。並べる順も乱数。

### 2.3 操作
- **ドラッグで置く**：ピース置き場のピースをドラッグして枠の上で離すと、いちばん近いマス目に吸い付いて置かれる。
  - 置けるのは、ピースのすべてのマスが枠の中の空いたマスに入るときだけ。置けないときは、ピース置き場に戻る。
  - ドラッグ中は、離したら置かれる位置にうすい影を出す（置けないときは出さない）（判断）。
  - ドラッグ中のピースは指の少し上に出す（判断。指でピースが隠れないように。ずらす量は実装者）。
- **置いたピースを動かす**：盤のピースもドラッグで動かせる。置けない所で離すとピース置き場に戻る。置き場の上で離しても戻る。
- **えらぶ**：最後にさわった（タップした・ドラッグした）ピースが「えらばれた」状態になり、ふちが光る。
- **まわす（右回り）・うらがえす（左右）**：ボタンで、えらばれたピースに効く。
  - 置き場のピースはその場で向きが変わる。
  - 盤のピースは、同じ場所で向きを変えて置けるならその場で変わる。置けなければ新しい向きでピース置き場に戻る（判断）。
  - えらばれたピースがないときは、ボタンを押せない見た目にする。
- 1本指の操作だけで遊べる。2本目の指は無視する（判断。同時に2つドラッグしない）。

### 2.4 クリア
- 枠のマスがすべて埋まった時点でクリア（答えの一例と並べ方が違ってもよい）。
- クリアした絵はずかんに「できた」として残る。ヒントを1回も使わずにクリアした絵には「キラキラ」も残る。一度ついたキラキラは消えない。

### 2.5 ヒント
- 「ヒント」ボタンを押すと、**答えの一例のとおりに置かれていないピース** を1つ選び、その正しい場所・正しい向きに、うすく光る影を **2秒** 出す（判断）。ピースは自動で置かない。
- 選ぶピース：答えの一例と同じ場所・同じ向きに置かれていないピースのうち、置き場にあるものを優先し、その中から乱数で1つ（判断。盤のピースを動かす必要があるヒントは後回しにする）。置き場が空なら盤のピースから選ぶ。
- その場所に別のピースが置かれていても、影は出す（そのピースをどけるのは子どもに任せる）。
- 回数の制限はない。1回でも押したら、その回は「ヒントを使った」になる。
- 「さいしょから」（§4.5）で新しい分け方になったら、「ヒントを使った」は消える（判断。分け方が変わると前のヒントは役に立たないので、新しい回として扱う）。
- 影を出している間にもう一度押したら、影を出し直す（同じピースを選び直してよい）。

### 2.6 むずかしさと絵の大きさ
- むずかしさは絵ごとに決まっている（ずかんのページ＝むずかしさ）。絵の大きさで差をつける。

| むずかしさ | 枠のマス数 | 絵の大きさの上限 | ピースの数の目安 |
|---|---|---|---|
| かんたん（`easy`） | 20〜30 | 24×24 ドット（6×6 マス） | 4〜7 |
| ふつう（`normal`） | 30〜40 | 28×28 ドット（7×7 マス） | 6〜9 |
| むずかしい（`hard`） | 40〜50 | 32×32 ドット（8×8 マス） | 8〜11 |

- 範囲は試作の絵（りんご 30・うんち 25・ねこ 40）に合わせて決めた（判断）。境目の 30・40 はどちらのページにも置いてよい。手動テストで調整する前提で `constants.js` にまとめる。

## 3. 絵（ずかんの中身）

### 3.1 テーマ
- どうぶつ・くだもの・子どもが喜ぶもの（うんち など）。ユーザーの指定。
- 最初の版は **各むずかしさ8まい、全部で24まい**。
- 絵の候補（判断。ユーザーは差しかえてよい。描いてみて形が崩れるものは同じテーマの別のものに替えてよい）：

| かんたん | ふつう | むずかしい |
|---|---|---|
| りんご、いちご、みかん、さくらんぼ、うんち、ひよこ、さかな、おばけ | ねこ、いぬ、うさぎ、コアラ、ぶどう、バナナ、すいか、ケーキ | くま、ぞう、ペンギン、かえる、パイナップル、メロン、にじいろうんち、ドーナツ |

### 3.2 描き方
- 絵はすべて本書作成者側（実装者）がオリジナルで描く。既存の作品・キャラに似せない。
- 文字の並びを1行ずつ手で書くと崩れるため、**まる・三角・四角などの図形を組み合わせて描く小さなプログラム**で作り、出てきたデータを §6 の形式で保存する（試作 `.claude/docs/specs/ui-drafts/fill-samples.html` のりんご・うんち・ねこがこの作り方。この3まいはそのまま使ってよい）。
- **絵を先に作り、ユーザーに24まいを見てもらってからずかんに載せる**（判断。絵は手戻りがいちばん大きく、過去に絵の案が2回見送られたため）。見る場は `fill-samples.html` と同じ形の一覧ページ。確認を待つ間は、絵に頼らない部分（piece・puzzle・engine）だけ進めてよい。
- 図形を組み合わせるプログラムは `tools/fill-pictures/fill-pictures.js`（Node。ゲームからは読まない）に置き、絵を足すときにも使えるようにする（判断）。実行は `scripts\run.bat fill-pictures`（判断。既存の `resize-images` と同じく run.bat に入口を足す。2026-11-17 計画時に `node` 直接実行から変更）。このプログラムが `games/fill/js/pictures.js` と見本の一覧ページ `.claude/docs/specs/ui-drafts/fill-samples.html` を書き出す。
- 共通の描き方（判断。試作で「かわいい」と判断された見た目）：濃い色の外ぶち1ドット、右下に少し暗い影、顔のあるものは黒い目＋白い光・ピンクのほっぺ。色は1まい8色以内。

### 3.3 絵を増やす（アップデート）
- 絵はすべて `games/fill/js/pictures.js` の配列に1件ずつ書く。絵を足すときはこの配列に1件足すだけで、ずかんに並ぶ（ほかのファイルは変えない）。
- 並び順は配列の順。むずかしさごとのページにはそのむずかしさの絵だけが並ぶ。

## 4. 画面と流れ

### 4.1 共通
- 共通ヘッダー（`Ailand.core.UI.header`）：「もどる」「おと」「せってい」。
- 背景の色とトーンは、ほかの5本と見分けがつく色にする（色は実装者）。見た目の土台は白いパネル・紺のふち（要件 1.9）。

### 4.2 流れ
入口 → **ずかん画面** → 絵をえらぶ → **プレイ画面** → 完成 → **できた画面** → 「つぎの絵」か「ずかんにもどる」。

### 4.3 ずかん画面
- 上でキャラを1体えらぶ（4体の顔を並べる。前回のキャラが選ばれた状態）（判断。ぷにっちの設定画面に当たるものをずかん画面に入れる。開始までのタップを減らすため）。
- タブ「かんたん」「ふつう」「むずかしい」。前回開いていたタブで開く。
- 絵のカードを並べる：
  - まだの絵：枠の形だけを灰色のかげで出し、「？」を重ねる（判断。形がわかると「これは何だろう」と思える）。
  - できた絵：色つきの絵と名前。
  - キラキラつき：カードのふちをキラキラさせる（`prefers-reduced-motion` のときは光らせず、星のしるしだけ）。
- タブの見出しの近くに「できた ○／8」と「あと ○まい」（全部できたら「ぜんぶ できた！」）。
- カードをタップするとその絵で遊ぶ。できた絵ももう一度遊べる（キラキラはまだなら取れる）。
- 初めて開いたときだけ、遊び方を1画面で見せる（「ピースを ドラッグして わくに おこう」「まわす・うらがえす で むきを かえよう」「ぜんぶ うまったら えが でてくるよ」の内容。文言は実装者）。2回目からは「あそびかた」ボタンで見られる。

```

 (まめ)(くち)(みみ)(ふら)   ← キャラをえらぶ
 [かんたん][ふつう][むずかしい]   できた 3／8
 ┌────┐┌────┐┌────┐┌────┐
 │りんご││ ？ ││ うんち ││ ？ │
 └────┘└────┘└✨✨┘└────┘
 ┌────┐┌────┐┌────┐┌────┐
 │ ？ ││ ？ ││ ？ ││ ？ │   あと 5まい！
 └────┘└────┘└────┘└────┘
```

### 4.4 プレイ画面
- 盤（枠）、ピース置き場、ボタン（まわす・うらがえす）、ヒントボタン、選んだキャラ（反応する顔と吹き出し）、絵の名前の代わりに「？」と何まい目かの表示（判断。名前は完成まで隠す）。
- カウントダウンはしない（判断。時間がないので要らない）。
- iPhone 縦（390×844px）で、盤・キャラ・置き場・ボタンがすべて収まり、スクロールしないこと。置き場はピースが11こまで並べられること（ピースを置き場の中で縮小して並べてよい。ドラッグを始めたら盤のマスの大きさに戻す）（判断）。
- iPad 横・PC：左に盤、右にキャラ・置き場・ボタン。iPhone 横は盤を小さくしても遊べる配置にする（実装者）。
- ボタンは 64×64px 以上（要件 1.2）。

```
iPhone 縦                          iPad 横・PC
 ← もどる  ？(3まいめ)  [ヒント]      ┌───────────────────────────────┐
 ┌─────────────────┐               │ ┌──────────┐  (キャラ)「いいね！」 │
 │   盤（枠）       │               │ │          │  ┌──────────────┐  │
 └─────────────────┘               │ │  盤（枠） │  │ ピース置き場  │  │
  (キャラ) 「いいかんじ！」          │ │          │  └──────────────┘  │
 ┌─────────────────┐               │ └──────────┘  [↻まわす][⇋うらがえす]│
 │ ピース置き場     │               │                      [ヒント]      │
 └─────────────────┘               └───────────────────────────────┘
  [ ↻ まわす ]  [ ⇋ うらがえす ]
```

### 4.5 一時停止・やめる
- 画面が隠れると `core/loop.js` のループが止まるので、戻ったとき（`visibilitychange` で表示に戻ったとき）にプレイ中ならループを動かし直す（ヒントの影・はずみ・完成の演出を続けるため）。BGM は `core/bgm.js` の既存の扱いで止まる。
- プレイ中の「もどる」：1まいも置いていなければすぐずかんへ。置いていれば「やめる？」を聞く（判断）。
- 「せってい」の中身：「さいしょから」（同じ絵を新しい分け方で）と BGM の ON/OFF（判断。ぷにっちと同じ並び）。

### 4.6 できた画面（完成の演出のあと）
- 絵を大きく出し、名前「○○ ができた！」。キャラは大喜び（`excited` か `cheer`）。紙吹雪。
- 「ずかんに はったよ」。キラキラを初めて取ったときは「キラキラ ゲット！」も出す。そのむずかしさの絵が全部できたら「○○ ぜんぶ できた！」。
- ボタン：「つぎの え」（同じむずかしさで、ずかんの並び順でこの絵より後ろの、まだできていない絵。なければ前から探す。全部できていれば並び順で次の絵）、「ずかんに もどる」。

## 5. キャラの反応と演出

### 5.1 選んだキャラ
- ふだんは `normal`。
- ピースが置けたとき：**3回に1回くらい** `joy` と短いセリフ（判断。毎回はうるさい）。最後の1こを残したとき（のこり1こ）は必ず反応する（`excited`）。
- ヒントを押したとき：`thinking`＋セリフ。
- 置けずに置き場に戻ったとき：反応しない（判断。自分の操作の直後にいやな顔をしないため。要件 1.6）。
- 完成：`excited` か `cheer`。ヒントなしなら `love` も候補（判断）。
- `worried`・`sadness`・`anger`・`panic` はこのゲームでは使わない。
- 同じ表情を3回続けない（要件 1.6。ぷにっちの `reactions` と同じ作り）。

### 5.2 盤の上の演出
- 置けたとき：ピースが「ぴたっ」と小さく弾む（判断）。
- 完成の演出（この順）：
  1. 最後のピースがはまると、全部のピースが一度光る。
  2. ピースがふわっと消えて、ドット絵が浮かび上がる（全体で約1.5秒。実装者）。
  3. 絵の名前とキャラの大喜び、効果音。
  4. できた画面（§4.6）。
- `prefers-reduced-motion` のとき：弾む・光る・紙吹雪・キラキラを止め、ピースが消えて絵が出るだけにする。

### 5.3 画面全体の演出（要件 1.6 の「1つだけ」）
- 画面全体の演出は完成のときの1つだけ。ピースを置いたときは盤の上の小さな演出だけ。

### 5.4 セリフ
- `games/fill/js/lines.js` に、キャラごと・状況ごとに持つ。20文字以内、ひらがな多め、公式セリフは使わない。口調は各キャラの `voice` に合わせる。
- 状況と数：`start` 3つ以上、`place`（置けた）5つ以上、`last`（のこり1こ）3つ以上、`hint` 3つ以上、`clear` 3つ以上、`sparkle`（ヒントなしで完成）3つ以上、`pageDone`（そのページ全部できた）3つ以上。
- 選び方は `core/line-picker.js`。

### 5.5 音
- 効果音（`Ailand.core.Sound.register`、名前は `fill-` で始める）：つかむ、置けた（ぴたっ）、置き場に戻る、まわす、うらがえす、ヒント、完成、キラキラ。音色は実装者。
- BGM（`core/bgm.js`）：ピタうめっち用の曲を新しく1曲作る。落ち着いて考えられる曲調（判断）。`.claude/docs/specs/2026-11-12-bgm-variety-design.md` の作り方と制約に従い、既存の曲名や旋律に似せない。

## 6. 絵データの形式

```js
{
  id: 'cat',            // 半角英小文字・数字・ハイフン。重ならない。保存のキーにも使うので、出したあとは変えない
  name: 'ねこ',          // ずかん・できた画面に出す名前
  level: 'normal',      // 'easy' | 'normal' | 'hard'
  palette: { o: '#f5a742', k: '#4a3020' },   // 1文字 → 色。'.' は使わない。8色以内
  pixels: [             // 1行＝横1列のドット。'.' はすきま
    '....kk................kk....',
    // …
  ]
}
```

- 幅（1行の文字数）と高さ（行の数）はどちらも4の倍数で、§2.6 の上限以下。すべての行が同じ長さ。
- `pixels` の文字は `palette` のキーか `.` だけ。
- 枠（§2.1）のマス数は §2.6 の範囲内。枠は上下左右で1つにつながっている。
- 完成した絵は `pixels` のとおりに描く（すきまのドットは描かない。1マスの中にすきまのドットがあってもよい）。

## 7. 作り（ファイル構成）

- `games/fill/` に作る（`index.html`・`css/fill.css`・`js/`）。`<html data-base="../../">`。
- ゲーム id は **`fill`** のまま（`core/games.js` がすでに使っている）。表示名を「ピタうめっち」にする。
- `js/` の分け方（ぷにっちにならう）：
  - `namespace`
  - `constants`：むずかしさの表、ピースの大きさ、ヒントの時間、反応の割合。
  - `piece`：**純粋で、ほかのファイルに頼らない**（`Ailand.games.fill` 以外の名前を使わない。`core/rng.js` も直接呼ばず、乱数の関数を引数で受け取る）。中身は、マスの並びの正規化・右回り・左右裏返し・向きの一覧・置けるかの判定・枠をピースに分ける。ピースじんとりを作るときに `core/` へ移すため（§12 の案1）。
  - `pictures`：絵データの配列（§6）。
  - `puzzle`：絵 → 枠のマス、種 → 分け方（答えの一例）・置き場の向きと順。純粋。
  - `engine`：遊びの状態（どのピースがどこに・どの向きで置かれているか）、置く・取る・まわす・うらがえす・クリア判定・ヒントで選ぶピース。純粋で DOM なし。イベントを返す（置けた、戻った、のこり1こ、クリア、ヒント）。
  - `lines`・`reactions`（表情の選び方。純粋）
  - `controller`：流れ（ずかん・プレイ・できた）、保存。DOM なし。
  - `layout`・`render`（Canvas：盤・置いたピース・影・ヒントの影・完成の絵）・`drag`（Pointer Events でのドラッグ・吸い付き・置き場との行き来）・`fx`・`sounds`・`ui`・`main`。
- 盤は Canvas、置き場・ボタン・キャラ・ずかんは HTML（判断。テトリっち・ぷにっちと同じ形）。置き場のピースとドラッグ中のピースの描き方（小さな Canvas か HTML か）は実装者。
- `devicePixelRatio` に合わせてくっきり描く。`getImageData` 等で読み出さない（要件 1.1）。絵はデータから `fillRect` で描く。
- 入力は Pointer Events。ドラッグは `setPointerCapture`。盤と置き場とボタンは `touch-action: none`（要件 1.2）。ただしずかん画面だけは `touch-action: pan-y`（背の高いずかんを縦にスクロールできるようにしつつ、ピンチ拡大は止める。要件 1.2 からの意図した例外）。
- ピースの色：4キャラのイメージ色（`Ailand.core.Characters` の `colors.main`）を順に使う（判断。答えの一例でとなり合うピースが同じ色にならないように割り当てる。4色で足りないときは同じ色がとなり合ってよいが、ピースの境目に濃い線を描いて見分けられるようにする）。
- 時計・きろく・押しっぱなしは使わない。テトリっち・ぷにっちのファイルは変えない。
- core の変更：`games.js` の fill 行を `name: 'ピタうめっち'`・`href: 'games/fill/index.html'`・`ready: true`・`saveKey: null` にする。それ以外の core は変えない（必要になったら本書に追記してから変える）。
- 入口のカードの絵は、遊べる状態の見た目にする（実装者）。
- README のゲーム一覧の行を「ピタうめっち／遊べる」にし、内容を1行で書く。CHANGELOG に1行足す。

## 8. 保存

- `Ailand.core.Storage.create('fill')` を使う。キーは `ailand:fill:` で始まる。
  - `settings.v1`：`{ char: id, tab: 'easy'|'normal'|'hard', seenHowTo: true|false }`。読めない値は既定（最初のキャラ・かんたん・false）。BGM の ON/OFF はぷにっちと同じく core の `Sound` 側の設定を使い、ここには持たない。
  - `zukan.v1`：`{ <絵の id>: { done: true, sparkle: true|false } }`。読めない値・知らない絵の id は無視する。絵が配列から消えても記録は消さない（判断。あとで戻したときに残っているように）。
- 保存するのはクリアした時点。途中の状態は保存しない（§11）。
- `games.js` の `saveKey` は `null`（判断。入口の「つづき」表示は途中の対局がある遊びのためのもので、ピタうめっちは途中を保存しないため）。

## 9. テスト

- 自動テスト（Node、`scripts\run.bat test`。`tests/test.html` に載せる。`tests/fill/` に置く）：
  - piece：正規化、右回り4回で元に戻る、裏返し2回で元に戻る、向きの一覧（形によって1・2・4・8通り）、置けるかの判定（枠の外・ほかのピースと重なる・空いている）、分け方（全マスが1回ずつ入る・どのピースもつながっている・4〜5マス・同じ種で同じ結果）。
  - pictures：**全部の絵**が §6 の決まりを守る（行の長さ・4の倍数・上限・文字・色数・枠のマス数の範囲・つながり・id が重ならない）。むずかしさごとに8まい以上。
  - puzzle：**全部の絵**について、いくつかの種で分け方が作れて §2.2 の決まりを守る。答えの一例のとおりに置くとクリアになる。
  - engine：置ける・置けない（戻る）、盤のピースを動かす、盤の上でまわせる／まわせないと戻る、クリアは答えと違う並べ方でもなる、のこり1このイベントは1回、ヒントは「正しく置かれていないピース」から選び置き場を優先する、ヒントを使った印。
  - controller：設定の保存と復元・読めない値、初回だけ遊び方、ずかんの記録（done・sparkle・一度ついたキラキラが消えない・知らない id を無視）、「つぎの え」の選び方、やめるときの確認の有無、「さいしょから」で「ヒントを使った」が消える。
  - reactions：`worried`・`sadness`・`anger`・`panic` を出さない、置けたときの反応の割合、同じ表情が3回続かない。
  - BGM：`tests/core/bgm-scores.test.js` にピタうめっちの曲を足す（ほかの曲と同じ確かめ方）。
- 静的チェック（`scripts\run.bat check`）が通ること。既存のテストがそのまま通ること。
- 手動テスト（ユーザーが行う）：iPhone 縦・iPhone 横・iPad 横・PC。ドラッグして置く・吸い付きのずれ・指でピースが隠れないか、まわす・うらがえすのわかりやすさ、置き場に11こ並んだときの見やすさ、ヒントのわかりやすさ、完成の絵のかわいさと驚き、「かんたん」を娘が1人で解けるか、「むずかしい」が難しすぎないか、ずかんを埋めたくなるか。
