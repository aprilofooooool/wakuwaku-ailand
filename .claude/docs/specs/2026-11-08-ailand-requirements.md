# わくわく！あいランド 要件ドキュメント

- 作成日：2026-11-08
- 状態：ユーザーと brainstorming で合意した内容（2026-11-08）
- 位置づけ：あいランド全体の仕様の正。食い違いが見つかったら推測で埋めず、ユーザーに確認して本書を直す。
- 実装方式（フォルダ構成・モジュール・テスト）は `.claude/docs/specs/2026-11-08-ailand-phase1-design.md` に書く。

## 0. 目的と利用場面

- 利用者：小学校中高学年の娘。相手はママやお友だち。
- 端末：iPhone（縦）と iPad（主に横）。PC Chrome でも動かす。
- 遊び方：スキマ時間に数分で1局。途中でやめても「つづきから」で再開できる。
- 「わくわく！あいランド」はミニゲーム集。入口ページでゲームを選ぶ。全7本（既存のオセロっち＋新作6本）。

### 0.1 守るべき体験（オセロっちで娘が気に入った点）

1. 好きなキャラを選べる。
2. 選んだキャラがかわいく反応する（表情とセリフ）。
3. 戦況に応じてかわいいエフェクトが出る。

### 0.2 直すべき不満

- オセロっちは「よわい」でも CPU に勝てなかった。新作の CPU は「よわい」で本当に勝てる強さにする（2.4 の目標値）。

### 0.3 アンチゴール（動いても失敗とみなすもの）

- 「よわい」CPU に娘がほとんど勝てない。
- 打った本人のキャラが、自分の手の直後にいやな顔をする。
- 1手ごとに演出が何重にも重なって、何が起きたかわからない。
- 旧オセロっち（flipflip-othello）の保存データを壊す。

## 1. 6本共通の要件

### 1.1 技術制約（移植元 request-prompt から継承）

- 素の HTML5 / CSS3 / JavaScript（ES2017 以上）のみ。フレームワーク・ライブラリ・npm・バンドラ・外部 CDN・外部フォント・実行時の通信は使わない。
- `index.html` をダブルクリック（file://）で開いても全ゲームが動く。ES Modules・`fetch()`・別ファイルの Web Worker は使わない。IIFE でグローバル名前空間 `Ailand` に登録し、`<script src>` を依存順に並べる。設定データは `.js` で持つ。
- Canvas に画像を描くのは可。`getImageData` 等で読み出さない。
- 音声ファイルは置かない。効果音・BGM は Web Audio API で合成する。
- ファイル名・フォルダ名は小文字英数字とハイフン（拡張子のドット）のみ。参照の大文字小文字一致を static-check で検査する。
- 画面の文言はひらがな中心の易しい日本語。コード・識別子・コメントは英語。
- 公開予定 URL：`https://aprilofooooool.github.io/wakuwaku-ailand/`（GitHub Pages、相対パスのみ使う）。

### 1.2 端末・入力

- iPhone 縦（幅 390〜430px）・iPad 横・PC Chrome 最新版。iOS は向きを固定できないので、縦横両方のレイアウトを持つ。
- 2人同時操作は iPad 横と PC に限る。iPhone は交代制のみ。
- 新しく作る画面（入口・共通ヘッダー・ぽとん4・後続5本）は Pointer Events で入力を統一する。盤面と操作ボタンは `touch-action: none`、タップ領域は最小 64×64px、本文 18px 以上。
- オセロっちの操作部分（click 入力・48px）は今回変えない（決定事項 D7）。
  - 2026-11-09 追記：Phase 2 で共通規約に合わせた（`.claude/docs/specs/2026-11-09-othello-core-migration-design.md` §5 が上書き）。

### 1.3 動きの配慮

- `prefers-reduced-motion` が有効なときは、揺れ・点滅・跳ねる動きを止め、表情変化と静止した表示だけにする。

### 1.4 キャラ

- キャラはオセロっちの4体（まめっち・くちぱっち・みみっち・ふらわっち）。
- キャラ追加は「画像フォルダ＋共通プロフィール1エントリ＋各ゲームのセリフ」で済む。セリフ未定義のゲームでは共通の汎用セリフを使う。ただし Phase 1 のオセロっちは自前のキャラ定義（セリフ入り）を使い続けるため、オセロっちにも1エントリ足す必要がある（共通化は Phase 2 以降）。
- 画像がない表情は表情読み替え表（1.5）で手持ちの画像に読み替える。画像の読み込みに失敗したら `normal` → 色つき円＋顔文字の順にフォールバックする。
- セリフは公式セリフを使わない。1つ20文字以内、ひらがな多め。口調は移植元の調査 `../flipflip-othello/.claude/docs/research/2026-10-29-character-voice.md`（移植後は `.claude/docs/legacy-othello/research/`）と各キャラの `voice` 定義に合わせる。

### 1.5 表情読み替え表

手持ちの画像は `normal` `joy` `anger` `sadness` `panic` `thinking` の6種類。2026-11-12 に `worried` `surprised` `excited` `sleep` `smug` `cheer` `love` の7種類を4体分追加した（元画像は `assets-src/`）。

| 論理表情 | 画像（いま） | 付けるマーク | 画像を追加したら |
|---|---|---|---|
| normal | normal | なし | — |
| joy | joy | なし | — |
| anger | anger | なし | — |
| sadness | sadness | なし | — |
| panic | panic | なし | — |
| thinking | thinking | なし | — |
| worried | worried | なし | 追加済み（2026-11-12） |
| surprised | surprised | なし | 追加済み（同上） |
| excited | excited | なし | 追加済み（同上） |
| sleep | sleep | なし | 追加済み（同上） |
| angry-steam | anger | 湯気 | （予約） |
| smug | smug | なし | 追加済み（2026-11-11 キャラたたきで論理表情を追加、2026-11-12 画像） |
| cheer | cheer | なし | 追加済み（同上） |
| love | love | なし | 追加済み（同上） |

- 論理表情名は英小文字（必要ならハイフン）で、追加画像のファイル名にそのまま使う。
- 画像を追加したら、表情読み替え表のコード（`core/emotion-map.js`）の読み替え先を書き換えるだけで、その画像が使われる。

### 1.6 演出の原則（オセロっちから継承）

- 手を打った本人には、自分の手の直後にいやな表情を出さない（喜ぶか、反応なし）。
- 画面全体の演出は1手につき1つだけ。複数のできごとが重なったら、ゲームごとの優先順で1つ選ぶ。顔の表情はキャラごとに個別に変わってよい。
- CPU と遊ぶときは、画面全体の演出を人間の側から見て決める。
- 同じ感情が2回続いたら3回目は別の感情にする（重み付き抽選があるゲームのみ）。

### 1.7 音

- 効果音と BGM は Web Audio で合成する。最初のタップで AudioContext を作るか resume する。
- 効果音と BGM の音量を分けて持つ。共通ヘッダーの「おと」で全体を ON/OFF する。
- 消音スイッチ（iOS）が ON のときに鳴らないのは許容する。

### 1.8 保存

- localStorage のキーはすべて `ailand:<ゲームid>:` で始める（共通設定は `ailand:core:`）。根拠：旧オセロっちと同じオリジンなので、キーが同じだと旧データと衝突する。
- 対局中のゲームは手ごとに自動保存し、入口から開き直すと「つづきから」で再開できる。
- 前回の設定（人数・キャラ・強さ・ルール）を記憶する。

### 1.9 画面の共通部品

- 共通ヘッダー：「もどる」（入口へ）・「おと」・「せってい」。オセロっちにも付ける。
- 見た目の土台はオセロっちのトップ画面（白いパネル・紺の太いふちどり・影・丸ゴシック・ポップな配色）。ただしゲームごとに背景の色とトーンを変え、どのゲームを開いているか間違えないようにする。

### 1.10 画像

- 表示用画像は 512×512 の透過 PNG（`assets/characters/<id>/`）。元画像（1264px）は `assets-src/characters/<id>/` に置き、ゲームからは読まない。
- 縮小は PowerShell＋System.Drawing のツールで行う（`scripts\run.bat resize-images`）。

## 2. 入口ページ

- タイトルロゴ「わくわく！あいランド」：ロゴ案 v2 の B（`.claude/docs/specs/logo-drafts/logo-v2.html` の B）で確定。
  - 「わくわく！」と「ランド」はオセロっちと同じ1文字ずつ色違いの文字（紺の太いふちどり＋影）。
  - 「あい」はピンクのハート型シールの上に白い太字で載せ、ほかより大きくする。
  - 動き（`prefers-reduced-motion` 無効時のみ）：文字が順にぽんっと出てゆらゆら揺れる。シールがゆらゆら傾く。
  - 画像ファイル・外部フォントは使わない（HTML＋CSS＋インライン SVG）。iPhone 縦 390px で2行に収まり、文字が切れない。
- ゲームカード：遊べる2本（ぽとん4・オセロっち）を押せるカードで並べる。未実装の5本は「じゅんびちゅう」のカードとして名前と小さな絵を薄い色で表示し、押せない。

## 3. ぽとん4（重力付き四目並べ）

- ゲーム id：`drop4`。表示名：「ぽとん4」。

### 3.1 基本ルール

- 列を選ぶとコマが一番下の空きマスまで落ちる。自分のコマが縦・横・斜め（2方向）に4つ並んだら勝ち。
- 満杯の列には置けない。
- 盤（横×縦）：2人 7×6、3人 9×7、4人 10×8（4人チーム戦も 10×8）。試作後に調整する前提（決定事項 D5）。
- 手番：2人・3人・4人は席順に巡回する。4人チーム戦は A1 → B1 → A2 → B2 の順で、チームが交互になる。
- 先手：2人のときは「じぶん／あいて／ランダム」を選ぶ。3人以上はランダム。

### 3.2 4人チーム戦（2対2）

- 同じチームの2人のコマが混ざって4つ並んでも、そのチームの勝ち。
- 同じチームの2人のコマは同じ系統の色にする（例：ピンクとうすピンク）。

### 3.3 オプションルール「ぬきとり」（公式 PopOut 準拠）

- 自分の手番に「上から落とす」か「一番下の段にある自分の色のコマを1つ抜く」かを選ぶ。抜くと、その列のコマが1段ずつ下がる。
- 抜けるのは自分の色のコマだけ（チーム戦でも味方のコマは抜けない）。おじゃまブロックは抜けない。
- 抜いた結果、自分と相手が同時に4つそろったら、抜いた人（チーム戦ではそのチーム）の勝ち。
- 抜いた結果、抜いた人以外だけがそろった場合は、そろった人の勝ち。複数人が同時にそろったら、抜いた人の次の手番から席順で最初の人の勝ち（3〜4人のみで起きる。本書作成者の判断）。
- 出典：Hasbro Connect 4 説明書（英国版 PDF）の PopOut 節。同時成立・満杯時の扱いは公式に記載がなく、本書で決めた。

### 3.4 オプションルール「おじゃまブロック」

- 1人2個ずつ（1局で）。自分の手番に、コマを落とす代わりにブロックを落とせる。ブロックも重力で落ちる。
- ブロックは灰色で、だれの並びにも数えない。抜けない。
- CPU も使う（「よわい」はほとんど使わない、「つよい」は相手のリーチを止めるときに使う）。

### 3.5 終局

- 4つそろったら勝ち。
- 盤が満杯になったら引き分け（ぬきとり ON でも）。
- 全員の手数の合計が「盤のマスの数 × 2」に達したら引き分け（ぬきとりの往復で終わらない対局を防ぐ）。

### 3.6 CPU

| 強さ | 目標 |
|---|---|
| よわい | 娘が10回中7〜8回勝てる |
| ふつう | 娘が10回中5回くらい勝てる |
| つよい | ママが本気で遊んで勝ったり負けたりする |

- 目標は Node で「子ども役の簡易 CPU」と対戦させて勝率で調整する（設計書に定義）。
- CPU は最低 0.6 秒待ってから打つ。思考中はキャラが「かんがえ中」になり「うーん」と出す。
- 「ふつう」の思考時間は1手あたり 0.5 秒以内（Node 計測の最大値）。
- 3〜4人でも CPU を混ぜられる。CPU の強さは全 CPU 共通で1つ選ぶ。

### 3.7 設定画面（対局前）

オセロっちのトップ画面と同じパネル形式。背景の色とトーンはオセロっちと変える。

1. なんにんで あそぶ？：2人／3人／4人／4人チーム戦
2. せきと キャラ：席ごとにキャラ（重複不可）と「ひと／CPU」。既定は 1P がひと、ほかが CPU。
3. CPU の つよさ：よわい／ふつう／つよい
4. ルール：ぬきとり ON/OFF、おじゃまブロック ON/OFF（既定はどちらも OFF）
5. どっちが さき？：2人のときのみ
6. はじめる（中断データがあれば「つづきから」も出す）

### 3.8 操作（操作案 A で確定）

- 盤の下に「おとす／ぬく／ブロック（のこり数）」の切り替えボタンを置く。ぬきとり OFF なら「ぬく」を、おじゃまブロック OFF なら「ブロック」を出さない。
- おとす：列をタップ → 盤の上にうすいコマ（ゴースト）が出る → 同じ列をもう一度タップで落ちる（2タップ）。別の列をタップするとゴーストが移る。PC はマウスを乗せるとゴーストが出て、クリック1回で落ちる。
- 列の当たり判定は、盤の上端から下端まで列の幅いっぱい。
- ぬく：抜ける自分のコマが光る → 光ったコマをタップ → もう一度タップで抜ける。抜いたら「おとす」に戻る。
- ブロック：落とすものが灰色ブロックに変わる。落としたら「おとす」に戻る。
- 「1手もどす」：人間1人と CPU で遊ぶときだけ、1局で3回まで。人間が2人以上いるときは出さない。

### 3.9 キャラの反応（演出表）

| できごと | 条件 | 打った人 | ほかの人 | 全体の演出・音 |
|---|---|---|---|---|
| place | 下のどれにも当たらない | 変化なし | 変化なし | 落下音（2回はねる） |
| リーチ | 打った結果、次の1手でそろうマスが「いま置ける場所」にできた | joy | worried | 「！」と光る音 |
| ブロック | 相手（チーム戦では相手チーム）の「いま置けるそろうマス」に置いた（ブロック含む） | joy（「とめた！」） | 止められた人：anger | ガード音と盾のマーク |
| ダブルリーチ | 打った結果、そろうマスが2か所以上できた | excited | surprised | キラキラと特別な音 |
| 終盤 | 空きマスが盤の4分の1以下になった（1局1回） | 全員 thinking | 同じ | BGM のテンポが上がる |
| 勝利 | 4つそろった | excited（大きく表示して動かす） | sadness | そろった4つが光る・紙吹雪・ファンファーレ |
| 引き分け | 満杯または手数上限 | joy（「いいしょうぶ！」） | 同じ | やさしい音 |
| CPU 思考中 | CPU の番 | thinking＋「うーん」 | — | 考え中の点々 |

- 全体の演出の優先順：勝利 → ダブルリーチ → ブロック → リーチ → 終盤 → place。
- ぬきとりの結果も同じ条件で判定する。
- 勝利演出：勝った人のキャラ（チーム戦は勝ったチームの2人）を画面中央に大きく出し、CSS で跳ねる・回る・キラキラさせる。`prefers-reduced-motion` 有効時は動かさず大きく出すだけ。将来 GIF や連番画像に差し替えられるようにする。
- 勝者に人間が1人でもいれば勝利演出、勝者が CPU だけなら負けの演出（紙吹雪なし、負けの音、人間キャラは sadness）にする（1.6 の「人間の側から見て決める」による）。

### 3.10 セリフ

- 状況（place を除く演出表の各できごと＋開始のあいさつ）ごと・キャラごとに3種類以上。20文字以内、ひらがな多め、公式セリフは使わない。

### 3.11 音

- 落下音（バウンドに合わせて2回）、リーチ、ブロック、ダブルリーチ、勝ち・負け・引き分け、BGM（通常／終盤でテンポアップ）。音色・旋律・テンポは実装者が設計する。

### 3.12 中断・再開

- 手ごとに自動保存（キー `ailand:drop4:save.v1`）。入口から開き直すと「つづきから」で再開できる。終局で保存データを消す。

## 4. オセロっち（移植）

- 遊び心地と全機能を保ったまま `games/othello/` に移す。名前空間・保存キー・画像パス・テスト読み込みの置き換え以外のロジック変更をしない。
- 例外として共通ヘッダー（もどる・おと・せってい）を付ける。
- 保存キーは `ailand:othello:` に変える。旧オセロっちの保存データ（`otc.save.v1` / `otc.settings.v1`）は読まず、書かず、消さない。

## 5. 後続5本（概要のみ。詳細は各 Phase で決める）

表示名は仮。`core/` の設計で見越す要素を書く。

| 仮名 | 遊び | 主な入力 | 描画 | core に要るもの |
|---|---|---|---|---|
| キャラたたき | 穴から顔を出すキャラを制限時間内にタッチする。iPad 横・PC では2人が左右に分かれて同時に遊べる | 同時マルチタッチ | DOM＋CSS または Canvas | 複数 pointerId の同時追跡、タイマー、requestAnimationFrame のループ |
| ピース埋め | 形の決まった枠を、いろいろな形のピース（ポリオミノ）で埋める1人用パズル | ドラッグ配置・回転・反転 | DOM または Canvas | ドラッグ（pointer capture）、マス目への吸着、回転・反転 |
| ピース陣取り | 2〜4人でポリオミノを置き合い、自分の色のピースの角同士がつながるように広げる陣取り | ドラッグ配置・回転・反転 | DOM または Canvas | ピース埋めと同じ部品＋多人数 CPU |
| 落ちブロック | 落ちてくるブロックを回して並べ、横1列そろえて消す1人用 | タップ・スワイプ・ボタン | Canvas | 固定間隔のゲームループ、Canvas の高解像度対応、キー入力 |
| 落ちもの連鎖 | 2個1組で落ちてくる色玉を、同じ色4つ以上つなげて消し、連鎖をねらう | タップ・スワイプ・ボタン | Canvas | 落ちブロックと同じ部品 |

- 特定の既存ゲームの名前・キャラ・見た目・音楽は使わない。遊びの仕組み（ジャンル）だけを参考にする。
